**Goal:** Remove browser-persisted global-password Bearer while preserving every API path, editable draft and unknown mutation outcome.

**Architecture:** Existing `apiClient` and two streaming fetch consumers call a constrained same-origin Next BFF. One opaque HttpOnly cookie identifies a bounded, single-process memory record holding only the current native credential pair. **Tech stack:** Existing Next 16 / React / Axios / Zustand / TanStack Query / Vitest and Python Playwright harness. No new dependency installation, crypto recovery mechanism or durable token store.

**Spec:** [DEVICE_SESSION_PROTOCOL](DEVICE_SESSION_PROTOCOL.md), especially Web sections 5–6; [ADR-016](../7-DEVELOPMENT/decisions/ADR-016-memory-bff-sessions.md); unchanged native [ADR-015](../7-DEVELOPMENT/decisions/ADR-015-device-session-backend.md).

## Global constraints

- Default remains `legacy_password`; empty/unknown mode and Web/backend/version mismatch fail closed, never downgrade. Device Web transport version is `bff-memory-v1`; native protocol remains 1.
- One stable Node frontend request process and one API process; no Edge/serverless/multiple replicas, HMR continuity or rolling mixed-mode deployment claim.
- One `__Host-sw-session` cookie; Secure/HttpOnly/SameSite Strict/Path `/`, no Domain, fixed absolute deadline. Explicit loopback test mode uses `sw-session`. Only login writes it; logout/refresh/status/resources do not delete/set it or emit Clear-Site-Data.
- Current-pair custody is server-only memory. No native token/opaque handle in browser JSON/storage/SSR/logs; no raw result cache/replay, no durable cleanup queue, no new persistent crypto secret. API persists digests only.
- Access <=15 minutes, session absolute 30 days. 64 live/pending/reserved BFF slots; 8 combined login operations/pending confirmations; pending 60 seconds; 32 refresh followers; auth owner/probe 10-second deadlines; cleanup 4 concurrent, 5 seconds each, once, no queue. Backend cap remains 32 independently.
- Every unsafe Web request needs exact configured Origin plus `X-StudyWorkbench-CSRF: 1`; reject supplied foreign Origin even on reads. No browser/platform Cookie or fabricated identity forwarded; upstream fixed and redirects manual. Native passthrough is separately default-off/gated.
- No resource retries or automatic mutation replays. Preserve original streams/FormData, IDs/revisions and mounted editable state. Google NEEDS_REAUTH is not app auth expiry.
- All UI strings in 14 locales; semantic design tokens. Read installed Next route/cookie guides before coding, not outdated framework assumptions.
- Coupled frontend/API restart is an **operational activation requirement**, not permission to change live processes. Private ingress/native, Docker host/build, real secrets and toolchain gates remain separate.

### Task 2 — Bounded server custody, strict rotation and lifecycle

**Interfaces:** Store is a versioned `globalThis` registry shared by bundled Node routes. `RecordRef` is an internal immutable identity, never caller authority. `AccessSnapshot = {record:RecordRef,generation:number,accessToken:string,apiSessionId:string,accessExpiresAt:string,sessionExpiresAt:string}` stays server-only. Public `WebSessionMetadata = {session_id:string,access_expires_at:string,refresh_expires_at:string,generation:number}` contains no handle/token.

- `admitLogin(predecessor?:RecordRef): LoginAdmission` synchronously reserves slot, assigns admission sequence and captures relevant logout boundary before first await.
- `publishLogin(admission, validatedEnvelope): LoginPublication` publishes only if not fenced/older than highest successfully published admission; returns a one-response-only fresh handle and metadata, not a cached result.

- `confirmStatus(ref): Promise<AuthOutcome>` uses fresh protected probe and post-await identity/generation/phase/deadline validation.

- `captureAuthorizedRevocation(validatedCallerSnapshot,target): RevocationBoundary` rechecks caller and atomically captures record identities/admission boundary. Completion only updates that captured boundary, never rescans newer records.

Native calls are injected for deterministic tests; deadlines use an injectable clock. Request-local cleanup credentials must be discarded when skipped/finished; no serialization of registry/records. Every reservation/owner path releases in `finally`; synchronous retirement and global transitions never await a per-record lock.

#### Frozen Web wire contract (2026-10-21 integration decision)

- Login 201 and refresh 200 return only flat `{session_id, access_expires_at, refresh_expires_at, generation}`. Login is pending until safe status confirms it.
- Device status 200 preserves `{auth_enabled:true, auth_mode:"device_sessions", protocol_version:1}` and adds `web:{phase, session}`. `session` is metadata or null; phase is `anonymous|pending|authenticated|refresh-needed|reauth-required|unavailable`. No handle means anonymous, unknown/obsolete handle means reauth-required. A known handle is authoritatively probed; unavailable/busy probe is unavailable, never authenticated. Native readiness failure or mode mismatch is 503 `AUTH_UNAVAILABLE`.
- Errors use `{error:{code,message}}`: 401 `AUTH_PENDING`, 401 `ACCESS_EXPIRED` (refresh needed), 401 `AUTH_REQUIRED` (reauth), 429 `AUTH_BUSY` with bounded `Retry-After: 1`, 503 `AUTH_UNAVAILABLE`. Login additionally preserves sanitized native 400 `AUTH_INVALID_REQUEST`, 401 `AUTH_INVALID_CREDENTIALS`, and 429 `AUTH_RATE_LIMITED`. Every 401 has the Bearer challenge; device browser requests nevertheless send no Bearer.
- Session listing retains `{sessions}`. Native acknowledged revocation is 204 only. Own local signout returns 200 `{server_revocation:"unconfirmed"}` and deliberately bypasses native readiness/probe during outage, but still requires valid Web configuration, exact Origin/CSRF, bounded body and its existing own BFF handle. It grants no cross-record/global authority.
- Only successful login writes the stable cookie. Status/refresh/resources/revoke/local-signout write no stable-cookie or Clear-Site-Data headers. Internal record, handle and native token envelopes are never serialized as Web responses.
