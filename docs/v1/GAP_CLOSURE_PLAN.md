## 一、范围与执行纪律

- 原件、版本、引用、笔记、备份与恢复已经真实验证，不再以重复做外围功能替代核心交付。
- 私有凭据已建立，不重新生成、不写入仓库、项目 ZIP、日志或报告。
- Google 登录、持续保存会话、真实远端写入、模型凭据配置/数据发送、付费资源、网络安全设置分别遵循相应授权；“批准本计划”不等于一揽子授权这些行为。
- 模型和 Google 客户端不启用盲目自动重试；未知提交先核对任务/远端对象，再决定是否补做。
- 先用公开合成资料做端到端验证；个人资料仅在用户明确指定目的与接收服务后使用。
- 当前服务已停止；启动验证与长期托管是两个状态。已有本地重启证据不等于工作区删除后仍能恢复。
- 用户已明确指定 dot 云电脑作为测试服务器、ChatGPT Sites 私有网址作为入口。首先验证这一组合的受支持连接方式，不迁移后端、不先推荐购买 VPS；不能把已有公开博客复用为私有资料入口。
- 上游或平台没有的能力列为可行性门槛，不预先写出不存在的 SDK 方法，不用关闭安全检查换取“通过”。

## Review Focus：跨阶段必须覆盖的五类失败

1. 隧道与前端不在同一网络命名空间：Task 1 必须证明真实 assets/API/SSE/上传下载都到达目标进程，不能以绑定创建成功替代连通性。
2. 浏览器刷新/离开后远端任务仍在运行：Task 4/6 必须找到原任务和成果，不重复生成，也不声称已远端取消。
3. 来源从 A 切换到 B，但旧上下文仍存在：Task 2/5 必须有反例证明隔离；不能通过时继续拒绝严格问答。
4. OCR、导入或综合只处理部分内容：Task 3/V1.1 必须逐项展示缺失、失败和覆盖范围，不把空结果当完整成功。
5. 新内容输入后迟到的请求完成：Task 2/6 必须保留新的笔记/问题草稿和项目身份，不用旧结果覆盖新状态。

- [ ] 先补离线登录流程测试：重复点击复用有效 flow；取消/过期/浏览器未准备就绪有明确状态；未登录不得写假 connected；切换项目不串状态。
- [ ] 实现最小受支持登录交接；不能安全完成时保持 unavailable，准确给出所缺环境，禁止接收聊天里的密码或 cookie。
- [ ] 在需要时单独确认账号、专用 profile 持久化位置/用途和访问范围；用户通过安全登录入口完成认证。
- [ ] 先仅执行身份/列表只读核验，再让用户选定一个 notebook 做导入；不枚举并抓取全账号作为默认行为。
- [ ] 对列表明确显示 recent-only/incomplete；导入报告逐项区分原件、可取得文本、元数据、成果、缺失内容；同名不等于同一个来源。
- [ ] 实际导入选定内容，补传原件时明确关联，核对文本/版本；模拟与真实验证分栏，不随便升级引用为本地已核验。
- [ ] 验证重启后的连接、失效提示与显式重新登录；断开只影响应用连接，不宣称已撤销 Google 全局会话。

**PM 验收：** 用户知道正在登录哪个账号、授权给哪个应用、导入了什么和遗漏了什么；不能出现“连接成功但所有按钮仍无解释不可用”。

截至本计划调查，官方 [latest release](https://github.com/teng-lin/notebooklm-py/releases/latest) 仍指向 v0.8.5；官方 [新对话说明](https://github.com/teng-lin/notebooklm-py/blob/main/docs/troubleshooting.md#starting-a-brand-new-conversation-resolves-the-older-issue-659-workaround) 说明省略 conversation ID 会复用历史，而删除对话/`ask --new` 会不可逆删除旧历史，没有已证实的无损修复。执行时须再次核对版本，不能推断升级即可解决。

- [ ] 对已固定版本及执行当时的官方仓库/SDK 文档进行一次有结论的调查：是否存在无损创建独立会话、显式会话标识、精确选源、历史归属和并发隔离接口。
- [ ] 输出可行性记录：证据、版本、试验设计、可行/不可行/信息不足。不能只循环“等待新版 SDK”；本轮调查完成即关闭调查任务，真正问答门槛继续保留。
- [ ] 如可行，先写 fake/合同反例：A 范围历史不进入 B、空选源不扩大范围、并发问答不共享上下文、断线重连不串会话、旧会话历史不被删除。
- [ ] 再用获批公开测试 notebook 做最小真实试验，记录实际会话身份和调用范围；合同测试通过不替代真实试验。
- [ ] 只有真实反例和正确引用映射通过，才实现/启用适配器路径，并回归任务取消、未知提交、引用未映射行为。
- [ ] 若无安全接口，保留阻止。建议让独立模型承担严格选源问答，NotebookLM 保留迁移/同步/音频及官方网页使用；需用户同意这一产品取舍，不能声称已经实现原定 Google 问答。

**明确禁止：** 清空/删除原 notebook 聊天历史；把 `conversation_id=None` 当作已证实的新会话；静默复制整个资料库到临时远端 notebook；用自动化网页点击掩盖接口不确定性。

**PM 验收：** 用户得到明确原因和可行替代路径，而非灰色按钮、无限重试或虚假的“稍后恢复”。

## 四、V1.1 深层阅读，单独立项而非延后无期限

| 子项目 | 调研与实现边界 | 最小验收 | 依赖/取舍 |
|---|---|---|---|
| 扫描 PDF OCR | 从中文印刷文字与混合文字/扫描页起步；页级 OCR provenance、置信度、超时与降级；不覆盖旧解析 | 冻结公开扫描样本，报告字符错误/遗漏；旋转页、低清页、多栏、空白页均有真实结果，低置信度不伪装可信引文 | 先确定 CPU 可承受实现；若外部 OCR 需数据发送授权；复杂公式另立项 |
| PDF 精确框选 | 基于稳定的 page/text span 与实际 glyph bbox；统一页旋转/缩放坐标 | 典型中文/英文、多栏、旋转页在多缩放级别定位；无法可靠匹配时退回页定位 | `api/evidence_service.py`、`open_notebook/domain/evidence.py`、`PdfCanvas.tsx`；需要格式版本/旧备份兼容评审 |
| 全库综合 | 显式“综合模式”，遍历选定资料并分层摘要/归并；逐文件记录读到范围、失败、截断、成本与检查点 | 故意把关键信息放在每份文件末尾/低频章节，验证覆盖；缺页/失败不宣称全部已读；事实保留原文引用 | 不把现有 top-k 检索或有限采样换名字；先限定资料规模/预算，完成独立方案后实现 |
| Google Takeout | 只适配获准提供的真实样本格式，并保留原包/导入报告 | 版本不符、缺原件、重复导入、损坏项明确处理；不承诺导出包一定含全部内容 | 取得真实样本前不能冻结解析器结构 |

每个子项目先用样本确定质量门槛和费用/资源上限，再写独立实现计划、失败测试、实现与回归。未获新资源授权时，只做离线调查和公开样例验证。

更后续：测验/闪卡/思维导图等 Studio 功能按实际学习价值排序；视频/PPT 视觉理解、实时语音、多用户/收费/SSO 属独立版本，不纳入本轮核心缺口的完成承诺。

## 六、用户需要决定的最少信息

1. 平台网址：宿主选择已明确为 dot 云电脑，不再重复提问。开发方先查明 Sites 私有入口到该运行环境的受支持连接；只有具体配置需要确认或平台缺失接口时再提出精确问题。
2. 模型：用于真实验收的现有模型/端点、公开样例测试的费用上限；密钥走安全配置，不能发在聊天里。也可决定是否接受“独立引擎先行试用版”。
3. Google：登录时确认应用专用账号会话；只读导入明确一个 notebook；创建/同步/一次音频生成在测试前集中确认目标和范围。
4. 综合能力：核心闭环稳定后，选择 OCR、全库综合或 PDF 框选的先后，建议先全库综合与扫描资料可读性，精确框选随后。

未得到这些输入时，继续准备公开评测集、登录/会话可行性调查、部署能力矩阵与离线测试；只暂停依赖该输入的真实操作。

## 七、完成定义与停止条件

- **本轮计划完成：** 所有已知缺口均有对应任务/阶段、验收门槛与授权边界，用户可审阅决定，不假装技术闸门已解决。
- **个人试用版完成：** P1/P2/P6 实测通过，其他能力按真实状态展示，用户认可独立引擎先行取舍；允许明确的手动测试窗口与离线限制，不要求生产 SLA。
- **原 V1 核心完成：** 原验收矩阵要求逐项达标，尤其 Google 默认真实问答和外部访问；不能用试用版替代此定义。
- **单个调查停止：** 得到证实可行的实现路线，或证实当前不支持并给出安全替代；不进行无期限轮询或重复无效探索。
- **单个外部步骤停止：** 目标结果验证成功，或确实需要新信息/授权时暂停依赖步骤；可安全修复的失败应修复后复验。未知提交先核对，不盲重放。

计划不承诺固定日历完工日期；获得部署能力、模型和账号验证条件后，再按真实阻塞与验证耗时更新排期。
