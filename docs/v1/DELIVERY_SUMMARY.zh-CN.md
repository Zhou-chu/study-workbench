# 学习工作台 V1 开发交付说明

## 已经做成的部分

这是基于固定 Open Notebook 提交开发的分支，保留原来的 Next.js、FastAPI、SurrealDB 和任务 worker。

- 无需配置模型即可上传 PDF、Markdown、TXT，保留原件和不可变版本
- CPU 解析、中文词法检索、来源选择、历史证据和物理页定位
- 可编辑笔记、来源快照、任务状态与本地恢复
- 项目 ZIP 导出、校验和导入新笔记本；包含原件、证据、笔记、可见历史等，不打包应用凭据
- NotebookLM 连接器、导入/同步/音频任务协议与失败恢复已实现，但真实 Google 能力尚未验收

本轮后端测试 1211 通过、1 项默认跳过；该原生恢复用例已在独立数据库测试中另行执行，40 项全部通过。前端 289 项通过，类型检查、构建和 lint 通过（保留 7 条上游警告）。

真实本地测试使用磁盘上的 SurrealDB、API、worker 和 Firefox，不只是接口模拟。已跑通登录、阅读、笔记保存与刷新、导出下载、网页导入和恢复后的引用打开。十条已知引用在两份 PDF 中打开正确版本和物理页，PDF.js 实际渲染原件；390px 中文手机界面有全宽内容和导航抽屉。另有全新数据库/目录恢复测试，原环境文件删除后仍能恢复并再次导出。

测试覆盖率已实际测量：V1 后端文件行覆盖 81.08%、分支 68.38%；V1 前端文件行覆盖 83.03%、分支 67.69%。这些是包含单元、服务、组件和合同用例的套件覆盖率，未把独立浏览器测试混入统计，也不是功能完成率。详见 `COVERAGE.md` 的分母与补测前后记录。

## 2026-10-20 续开发新增

- 重新解析和归档历史引用重新核验均已接入任务、API 和阅读器；失败时保留旧可读版本，幂等重放不重复执行。
- 原生 Firefox 已跑通重新解析、上传新版后旧引用仍定位第 3 页、ZIP 恢复后核验 3 条引用全部通过、任务期间切换阅读器及刷新保持正确状态。
- 引用越界/无效状态不会被仅证明原文存在的核验覆盖。排队问答取消后不再锁住输入；严格 Google 能力在实际调用锁内再次检查。
- 过期本地维护任务通过状态轮询恢复同一个任务，跨进程锁防止重复执行；不宣称无人访问时后台恢复或维护 worker 强杀实测。

## 还不能宣称完成的部分

1. 没有实际登录 Google，也没有执行 Google 创建、同步、问答或音频生成
2. 当前固定依赖 notebooklm-py0.8.5 没有已确认的“无损开启全新对话”接口，严格来源隔离的 NotebookLM 问答会明确阻止，不会混用旧对话证据
3. 独立模型尚未配置，问答/提纲的模型协议使用注入式测试；不能当作真实模型答案质量验收
4. 没有可供外部浏览器访问的受保护 HTTPS 地址；本地监听地址不等于用户可访问的交付网址
5. 恢复包的历史“已核验”标记仍先降为“未核验”；现在可以显式重新解析保留原件来核验历史引用。只有引用原文及定位与新解析精确一致才恢复核验状态，不能证明原始文件真实性或陈述正确性；没有原件/不匹配的引用保持未核验
6. 生产密码、加密密钥和数据库凭据没有创建，等待明确授权；测试只使用隔离的公开固定测试值

## 文件怎么用

- `RUNBOOK.md`：依赖安装、运行、测试、持久化与后续步骤
- `ACCEPTANCE.md`：A01–A24 每项真实/模拟/受阻的状态
- `COVERAGE.md`：实测覆盖率、补测前后差异和已修复边界问题
- `NOTEBOOKLM_SDK.md`：SDK能力与严格问答限制
- `PORTABLE_FORMAT.md`：导出格式、恢复策略与安全检查
- `examples/public-fixture-project.zip`：不含个人数据的公开示例项目
- `evidence/`：测试日志、机器可读结果与浏览器截图

源码包不包含 node_modules、Python 虚拟环境、数据库运行文件、Google 会话或真实密钥。云环境文件目前可以跨命令保留，但环境被停止或删除后的生命周期尚无保证，应保存源码和项目导出包。
