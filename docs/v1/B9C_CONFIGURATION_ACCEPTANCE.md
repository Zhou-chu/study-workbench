## Owner and producer boundaries

One typed DraftRegistry configuration participant owns separate application/model resources; both B2 resource lookups, retained selection, retirement and before-unload use the existing owner. Existing notebook SettingsStore and AdvancedStore are unchanged. A stable mounted lease does not turn its own status transition into a newer navigation intent. Original tokens include frozen context/generation/provider/control/configuration revisions and immutable safe action/impact data; original unknown writes remain blocked without inferred replay authority.

The single settings adapter and existing setup-metadata owner are reused. Raw credential paths/URLs and provider diagnostics are projected out before publication. New keys/URLs/paths are private DOM refs/transient request values only; submit-finally, cancel, field replacement, retirement and ref detachment/unmount clear them. No mutation variables, request hashes, cache/storage/navigation secret copies or provider auto-actions. Stored fields are presence-only Keep/Set/Clear; blank edit keys omit, and Ollama zero is explicit reset.

Complete fresh credential and unfiltered model evidence distinguishes zero-link deletion from cascading deletion. Exact same-provider readable migration targets and affected defaults are captured; independent client reads are not a server CAS. No delete_models parameter, model-detail GET, provider sync, reindex/rebuild, default repair, generic jobs observer or new backend routes.

Discovery selection type is an explicit registration modality, not inferred provider capability or a server type filter. Missing/null remote type and empty-on-error are unverified. Case-insensitive name search, filtered toggles/custom selection and lowercased name-plus-type dedup preserve exact credential/discovery revision. HTTP200 success:false is displayed as failure. Partial environment migration retains all four safe counts under an uncertainty barrier. Auto-assign displays assigned/skipped/missing required slots only.

Matching defaults PUT can issue one normal guarded /advanced navigation, fenced by original token, mounted resource/location and newer navigation/control/metadata/context evidence. Cancellation, A-B-A, retirement, mismatch or unmount cannot redirect. The explicit Open Advanced link never resends PUT or starts Advanced work.
