# 产品经理视角体验红队：第一次使用学习工作台

日期：2026-10-21。**这是专家实际操作走查，不是真实用户访谈、可用性样本研究或量化转化实验。**

## 结论先行

核心的“上传 → 阅读 → 手写笔记 → 导出 → 恢复”可以在没有 Google 登录、没有模型的情况下实际完成。产品目前的问题不是缺少装饰，而是**先让新手看到不能做的事，后让他自己找到已经能做的事**。建议这一轮只做两个连贯改进：

1. 建立模型无关的第一步：空工作台直接提供“添加学习资料”，说明可先阅读、搜索和记笔记；明确阅读与提问选源的区别。
2. 把工程状态翻译为用户任务：保留真实限制和诊断详情，但不让 `PROFILE_MISSING`、`not_submitted`、长任务 ID 成为默认的主要叙述。

不要自动切换引擎、自动扩大选源范围、淡化 Google 严格选源限制，也不要把“连接成功”改写成“问答可用”。

## 优先问题（5项）

### 1. P1：空手机工作台先展示阻断，没有直接的本地起步路径

**实际证据：** `05-empty-mobile-zh.png`。进入 `/notebooks/{id}/study` 后默认选中“对话”，首先看到未验证 Google 和禁用提问。上传需主动切换“资料”。

**为什么难：** 用户还没有资料，首要任务不是选择问答引擎。页面暗示“我必须解决账号/模型问题才可以开始”；真实可用的阅读笔记价值被遮住。创建后的双入口也增加概念切换，但这轮不必重写上游导航。

**最小修复：** 无资料时在可见主区域给一句“先添加一份资料，可直接阅读、搜索和记笔记，无需先连接 Google 或配置模型”，一个“添加学习资料”按钮切换资料面板并把焦点落在上传控件。保留当前真实问答状态，不自动发起登录。不为已有关联远程资料的项目错误显示“没有资料”。

**验收：** 新空项目在 390×844 首屏能辨认下一步；键盘激活后上传控件获得焦点；上传后引导自然消失/更新；已有资料、恢复项目不被空引导遮住；不发生任何隐式网络写入或选源变化。后续可在创建成功后提供直接“打开学习工作台”，而非强制改变所有上游使用者路径。

### 2. P2：阅读、搜索与提问选择是三个概念，却只给一个“已选0项”

**实际证据：** `06-upload-mobile-zh.png`、`07-read-mobile-zh.png`。点击阅读后文档可见，头部仍已选0项；源文件的复选框与阅读按钮分离。手机外层“对话”页签包含内层“阅读/对话”。

**为什么难：** 新手可能把正在看的文档理解为提问对象；又可能为了能搜索而把所有版本全选。不能靠自动扩大范围“解决”这个问题。

**最小修复：** 在选源旁添加简短说明：“阅读不会改变提问范围；勾选的资料用于搜索和提问。”未选源时提供去选择资料的明确动作；让手机含阅读的页签叫“阅读与对话”或其他准确名称，注意窄屏不截断主要语义。

**验收：** 从空选源打开原件不会改变保存的 scope；提示让人知道下一步；勾选后数量变化；切换远程范围时提示不能错误声称本地搜索覆盖 Google 原文；键盘页签箭头/Home/End行为保留。

### 3. P2：未连接 Google 的完整控制台抢占注意，成功的本地任务又显示“未提交”

**实际证据：** `10-desktop-zh.png`。Google 区域显示 `PROFILE_MISSING`、额度未知、大量禁用创建/同步/音频控件；本地提取任务显示 `extract_evidence · job_…`、已成功、`提交状态：not_submitted`。手机资料区同样出现这些内容。

**为什么难：** “成功但未提交”看起来像没有保存；`PROFILE_MISSING` 像系统坏了。新手必须先理解内部协议才能判断自己的资料是否安全。直接隐藏一切错误同样损害信任。

**最小修复：** 未配置时显示“尚未连接 Google；本地资料仍可使用”，高级连接管理放入键盘可操作 disclosure；错误码保留在诊断详情。任务以“提取资料 / 导出项目”等本地化动作命名，完整 ID 在详情可复制；外部提交语义只在相关远程任务呈现，未知提交仍必须醒目解释可能消耗额度。

**验收：** 本地成功任务不再给出暗示失败的 not_submitted；断开与尚未验证不混同；严格选源不可用、需要重新登录、未知提交不能被折叠到用户看不见；不会自动连接/同步/重试。

### 4. P2：导出发起处只有任务编号，真正下载藏在另一面板

**实际证据：** `11-export-desktop-zh.png`。发起后头部显示任务号；右下任务卡最终提供“下载成果”。真实导出、下载、恢复完成。

**为什么难：** 用户目标是“把备份拿到自己手里”，不是“提交一个任务”。手机上另一面板不可同时看到，可能误以为已经下载或点击导出重复提交。

**最小修复：** 在发起处明确“正在准备备份，完成后到‘笔记与成果 → 任务’下载”，给跳转任务动作；更好是同一处跟踪该任务成功并给出“下载项目包”。不要把任务提交当作备份已下载。

**验收：** 无需记任务 ID 就能找到对应包；下载完成与服务端已生成区别明确；失败/未知状态不自动重发；恢复继续说明“新的本地笔记本”及缺失远程原件/历史边界。

### 5. P1（并行专项，非本走查故障实测）：失败必须保留原动作和可恢复上下文

并行审计确认需要覆盖：模型配置读取中/错误不能误放行；上传回包丢失需要同一幂等键人工重试；阅读首次请求失败需要原位置重试，不应强迫整页刷新。用户的情绪目标是“知道发生了什么、哪些内容保留、下一次点击是否会重复”，而不是换一个温柔但不准确的错误词。

**验收：** 修复后实测故障注入；阅读重试保留未保存笔记与问题草稿、页码/引用；上传提示“结果未确认”而非伪称未写入，同一键重试不产生新版本；模型状态未知期间不调用模型；任意未知远程提交禁止盲目自动重试。实际结果请链接专项证据，不以本文替代。

## 亲和力、移动端与可访问性判断

- 当前中性色阅读面、明确保存按钮、原件下载、备份范围说明是有效基础，不建议营销式 hero、彩色大卡片或过度拟人化。
- 当前手机没有本次可见的横向溢出；这只是两个尺寸下截图观察，不是完整响应式证明。面板内独立滚动会保留滚动位置，任务引导应主动定位目标，而不只切换页签。
- 字段可通过 label 定位，上传控件已有中文可点击外观；不能据此宣称完整 WCAG 合规。尚未执行屏幕阅读器、200%缩放、全键盘端到端和色彩对比专项。
- 不把长 ID、代码和真实边界删掉；把它们从“默认阅读任务”移到“需要时能找到的技术详情”。错误应描述用户能判断的状态与安全下一步，不责怪用户。

## 修复后复验清单

1. 中文桌面/手机，从空项目起步，无 Google/模型也能找到上传并阅读。
2. 使用 Tab/Enter 走“添加资料”，切换页签后焦点不丢失；现有页签键盘导航保留。
3. 读取原件不改变问答范围；明确勾选才改变 scope；搜索未选择时有可理解下一步。
4. 一份正常文件、一份失败文件同时上传，逐文件状态清楚；不靠刷新恢复。
5. 手写未保存笔记后触发阅读失败、重试，草稿仍在。
6. 导出等待到下载，再恢复新项目；用户能区分“已生成”“已下载”“已恢复”，缺失的 Google 资产仍清楚。
7. 联网未知、模型未知、Google 不支持严格选源分别准确呈现；不自动切引擎，不调用未经授权服务。

以上为修复前基线和验收建议；最终通过情况应由最终构建证据另行记录。

## 原问题4补充闭环：导出到下载（07:33 UTC）

前文截至07:20的 P2 待办现已完成限定范围修复与实际复验；历史基线保留，不回写成当时已经具备的体验。

**最终证据：** [continuation-2026-10-21f/browser/results.json](evidence/continuation-2026-10-21f/browser/results.json)，中文 Firefox，390×844，独立临时原生数据库/API/worker/生产构建。审核另行逐张检查排队、状态错误、文件就绪、下载错误、交给浏览器下载共5张截图。

- 同一个“项目备份”展开区完整承接“正在准备，尚未下载”→“项目包已生成，点击下方下载以保留副本”→“下载项目包”；不需要切换笔记与成果页签，也无需记任务 ID。
- 状态读取故障显示“刷新备份状态，不要重复导出”；真实 worker 随后完成导出。下载失败明确“再次点击下载项目包，无需重新导出”，重试的是同一个已生成文件。
- 完成反馈是“已交给浏览器下载，请在浏览器下载记录中确认文件已保存”，没有把开始下载冒充用户设备已持久保存。离开/刷新后的原任务查找位置仍有说明；Google 缺失原件和历史的备份边界保留。
- 实际键盘操作覆盖发起、状态刷新、下载与下载失败后的重试；全程 **1次导出POST、1个后端导出任务、2次同成果下载请求**。测试实际取得 ZIP v1，并核对原件字节、保存笔记、清单哈希。页面错误0，外部请求拦截记录0，没有 Google 或模型调用；服务已停止。
- 展开错误/完成状态时，手机备份区域占较多高度，连同导航约590–620px，剩余阅读区约220–250px。所有备份状态、下载按钮、说明及可收起标题仍完整可见，无横向裁切；这是用户主动展开的短期备份任务，收起后恢复阅读空间。此次评审不将其视为阻断，也不声称所有更小尺寸均已测试。
- 本次结果没有证明“任何状态查询都不自动轮询”：备份查询暂停行为由组件测试覆盖，已挂载的任务历史仍可能独立查询同一端点。关键安全结果是没有重复提交导出任务。

**结论：原问题4在指定中文手机、真实本地导出、状态读取及下载故障场景下闭环。** 不扩大为真实用户研究、全部下载/浏览器兼容性、用户设备保存保证或完整 Google 迁移验证。
