## 变化与边界

**证据详情读取。** 仅详情请求使用请求内首次读取复用和每批最多 128 个物理记录 ID，返回深拷贝，
保留顺序、重复项和错误优先级。172 条记录的模拟数据库边界用例中，SELECT 数从 **692 降至 4**，
并比较序列化响应 JSON 字节一致；这是查询次数及输出等价断言，**不是实际数据库运行或延迟测量**。
请求内复用不是事务快照；并发写入仍可能形成混合时点视图，总响应与缓存内存仍随证据量增长。

**三类存储完整性保护。** 将证据负载 ID 绑定到物理查询 ID；要求提取结果列表中的证据属于指定
版本及提取结果；引用验证核对保留提取结果的版本归属，并以请求 ID 判断是否属于提供给回答的证据。
物理 ID 与列表归属不一致的读取返回受控 400；引用验证（含直接证据响应中的验证字段）返回无效判定。测试覆盖损坏元数据前提下避免返回外来
引文或构造模型提示，不证明已有普通导入攻击路径，也不声称防住所有元数据损坏。

**同步来源处理失败保留。** 从初始保存开始，后续关联、SDK 提交/等待、失败结果或读取异常不再自动
删除来源、上传原件或已有子记录，也不自动重试；返回既有 HTTP 409 `COMMAND_SUBMISSION_UNKNOWN`、
`retry_safe: false`。已知 ID 只是检查线索，不是提交或队列成功证明；成功路径保持原契约，取消继续传播。
路由层不再直接记录这些原始错误细节，但**未证明底层数据库/SDK 日志全局脱敏**。
这不是完整 outbox、持久幂等、工作线程终止证明、孤立记录自动恢复或跨重载/标签页去重。
通用传输错误的手动重试及跨卸载恢复缺口仍在。
