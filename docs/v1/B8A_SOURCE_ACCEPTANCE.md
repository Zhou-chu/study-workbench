## Shared interfaces for later B8 slices

- `data/library-api.ts`: `createLibraryApi(WebTransport)` returns the real `sources`, `associations`, `insights`, `metadata`, `embed`, and `command` read/write groups. Callers supply the captured `DispatchContext`; each asynchronous response/body checks both that context and the session generation. Source `asset.file_path` is reduced to a boolean, never exposed as an address. Source/insight IDs are complete opaque strings and route construction uses `sourceHref`.
- `data/use-library-connection.ts`: consumes the existing session transport/context and QueryClient lifetime. `scope` includes epoch, exact target and session generation. It neither reads credentials nor creates a second cache.
- `DraftRegistry.library`: app-lifetime immutable `LibraryDraft` records with discriminated global/source/notebook/session/profile ownership, exact inputs and original File objects, captured context/generation/revision, attempt token and per-item receipts. Existing B8a input variants are import, metadata, associations, existing-source selection and explicit source actions. Ownership keys are canonical; unlink identity includes both source and notebook, and insight deletion includes the exact insight. Later slices may add distinct typed variants, not fake notebook IDs.
- `open` resumes unresolved original ownership; `begin` is a synchronous single-attempt latch. `item/finish/observe` accept only the matching token/current ownership. Pending/accepted/unknown and terminal receipt records are immutable. A late original acknowledgment may retain its real IDs but never turns an unknown operation back into success or unlocks it. `fresh` permits a separate current blank editor only for stale, definitely unsent/rejected input, retaining the old input/File and never unlocking unknown work. `retire/refreshFences` never rebind or replay.
- `useLibraryState` connects those records to the existing navigation controller; owner cleanup deactivates only its own active resource ID. Source/component dismissal retains state in the registry. Navigation captures both resource and notebook revision/activation; a clean source dialog cannot hide a dirty/pending notebook.
- `executeLibraryDraft` sends original inputs serially. Unknown batches stop, accepted per-target receipts remain, and reads are never used as proof of rejection. Only an explicit proven-undispatched first attempt may be manually submitted again. Completed/failed attempts need a separate new user intent; unknown ones stay locked.
- `LibraryCommandObservers` is mounted once inside WorkbenchSession. `observeCommand` observes only actual returned IDs, stops on every exact terminal state, treats three read failures as unknown, and never cancels remote work. Stop-checking retains the accepted operation and explicitly says server processing may continue. No component may add a second observer for the same operation.
- `SourceAsset` owns HEAD/GET-by-ID download, post-body context/activation checks and Blob revocation. It aborts/revokes on unmount, source change or scope change. Original URLs are http(s)-only without embedded credentials; YouTube rendering is explicit and limited to validated video IDs. No server path or arbitrary attachment/evidence identity is invented.
- `command-destinations.ts` contains only implemented notebook/source destinations. Later owners add their real destinations and handlers here; no placeholder Ask/podcast operation is registered.
- The independent retained-creation inspector only reads existing notebook creation snapshots and known receipts. It does not activate a creation owner, create a new intent, unlock or resend.
