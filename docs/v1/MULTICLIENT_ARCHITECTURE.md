# StudyWorkbench 多端原生体验与可迁移部署设计

> 日期：2026-10-21。状态：**完整设计已获用户批准；实施计划自主审查修订后直接推进，无需再次等待审阅**。
> 本文是已批准的设计规格与阶段路线图，不是已实现清单。逐文件任务、依赖与验收闸门见 [实施计划](MULTICLIENT_IMPLEMENTATION_PLAN.md)；安全的本地基础施工可直接推进，外部入口、实际凭据配置、工具链安装、收费与发行仍分别核对授权。

## 1. 决策、目标与边界

用户要求前后端 Docker 化、将来可以迁移，并为 Android、鸿蒙 6、iPadOS 分端并行开发；已选择“偏原生体验”，而非网页套壳优先。

确定的路线：保留 Web；Android 与 iPadOS 采用 React Native，共享移动端业务与适配后的界面；鸿蒙 6 使用 ArkTS/ArkUI 独立原生客户端。共享服务端协议与验收样例，不强求共享全部 UI 或任意 TypeScript 源码。

目标是同一个私人研究工作台在不同设备上可用：资料、引用、笔记、任务与成果身份一致；各端尊重本机文件、导航、无障碍与生命周期习惯。

- 不重写已经验证的资料版本、引用、笔记和项目导出恢复链路。
- 不将“多端源码存在”当成“多端应用已交付”，也不以外围开发代替真实模型和 Google 闭环。
- 不把 Docker 当成移动客户端的运行方式：Docker 承载 Web/API/worker/DB；原生客户端仍由各平台工具链构建和签名。
- 不承诺当前 dot 云电脑持续在线；单人测试允许明确的手动服务时段。
- 本文中的新目录、协议扩展、分支与默认值均为设计提案，尚未创建或启用。

依据：[原 V1 范围](DEVELOPMENT_PLAN.md)、[缺口闭环计划](GAP_CLOSURE_PLAN.md)、[现有 API](API_CONTRACTS.md)、[体验红队](UX_RED_TEAM_2026-10-21.md)、[真实验收设计](LIVE_ACCEPTANCE_SPEC.md)。

## 2. 当前证据与不可跳过的缺口

| 领域 | 已知现状 | 对本设计的约束 |
|---|---|---|
| 服务栈 | Next.js、FastAPI、SurrealDB、SQLite 和 worker | 保留职责，先隔离部署而非重构业务 |
| Web 鉴权 | 登录后实际将全局应用密码作为 Bearer 使用 | 不是设备会话；不能直接复制到所有客户端 |
| 浏览器依赖 | localStorage、window 跳转、DOM 下载、File/FormData、Next 代理 | 移动端需独立 transport 与平台适配，不能照搬网页库 |
| Docker | 现有 Compose 拉取上游镜像；根 Dockerfile 为合并进程镜像 | 不代表 StudyWorkbench 四服务方案已完成 |
| 当前 dot | Linux；未发现 Docker/Podman 或 Docker socket | 可以编写并静态检查，不能宣称本机已构建/启动容器 |
| 私有访问 | Sites 存在 tunnel binding 结构；此 dot 的受支持注册流程尚未找到 | 是待解能力缺口，不是已证实“不支持” |
| 真实 AI | 离线题库、模拟与集成测试不等于真实推理 | 真实模型质量验收仍独立阻塞交付 |
| Google | 应用可见登录及真实远端闭环未完成；严格会话隔离受 SDK 能力限制 | 保持能力闸门，不能由客户端绕过 |

当前源仓库 `feature/study-workbench-v1` 的 `origin` 指向上游 `lfnovo/open-notebook`；用户私有仓库 `Zhou-chu/study-workbench` 的 `main` 是过滤后的发布快照，两者不是可直接互换的提交历史。

## 3. 部署拓扑与服务职责

```text
Web 浏览器 ── Sites owner-private HTTPS ── 受支持私有连接 ── Web frontend
原生客户端 ── [私有入口鉴权验证通过后使用同一入口] ───────────────┘
                                                           │ /api 代理
                                                     API（单实例）
                                                      │        │
                                         本地共享数据卷       SurrealDB
                                                      │        │
                                                   worker（单实例）
```

四个 Compose 服务分别是 `frontend`、`api`、`worker`、`db`。API 与 worker 使用**同一个后端镜像**，通过不同启动命令运行，保证源码、依赖锁和任务定义一致。

- frontend：Next standalone，非 root；内部 API 地址固定服务名 `http://api:5055`，只接受允许的代理路径。
- api：鉴权、业务接口、迁移、现有任务调度；迁移成功后才进入就绪状态。
- worker：异步资料处理、模型/Google 任务；处理结果由持久化任务身份对外暴露。
- db：SurrealDB 独立数据卷；初次迁移保持已验证的 2.3.10，不同时升级数据库大版本。
- 仅 frontend 绑定宿主回环地址；API/DB 不发布宿主端口。互联网入口另经受支持连接建立，不以放开数据库端口解决连接问题。
- API/worker 首版各一个实例、同一宿主共享本地卷；现有 `fcntl.flock` 与 API 调度约束不支持直接横向扩容或跨主机共享文件锁。
- 容器停止、重建不删除持久卷；显式删除卷属于破坏性操作，需要独立确认。

计划部署产物位于 `deploy/v1/`：两个 Dockerfile、`compose.yaml`、入口配置校验脚本和无秘密的配置样例；迁移说明位于 `docs/v1/DOCKER_MIGRATION.md`。

构建前必须修正 `.dockerignore` 的运行目录排除，禁止 `.runtime`、秘密配置、Google profile、资料和备份进入 build context；不先构建再检查泄露。

镜像由当前项目源码与锁文件构建，不复用上游 `v1-latest` 充当定制版；基础镜像版本/摘要在验证后固定，不启动时临时下载安装可选依赖。

密码和加密密钥沿用 `_FILE` 读取；数据库凭据通过入口显式校验与安全注入，拒绝默认 root 密码或占位密钥。frontend 不持有 DB、加密密钥或模型凭据。

Next rewrite 的内部地址可能在构建时固化：必须验证可迁移的服务名代理方案、流式响应与 `/config` 同源行为，不能仅改运行时环境变量便宣称可移植。

启动顺序为 DB 就绪 → API 迁移完成 → worker/frontend；现有常量 `/health` 不代表数据库或任务健康，须补充有界 readiness 和一次无模型队列任务验证。

## 4. 私有入口与原生连接的双重可行性闸门

**闸门 A：dot 托管入口。** 查到受支持的精确 dot tunnel 注册方式后，确认连接器与真实 frontend 网络命名空间互通；验证 assets、API、上传、下载、事件响应和持久任务，而不是仅得到一个绑定 ID。

Sites 私有 URL 只作为入口，完整后端仍运行在用户指定的 dot 云电脑。不将 Python/DB 迁往 Workers，不复用公开博客，不把 `terminal.local` 内部预览地址当成公网交付。

**闸门 B：原生身份访问。** owner-private Sites 的平台身份与应用设备会话是两层独立认证。系统浏览器登录成功，不代表原生 HTTP 请求自动得到浏览器 Cookie。

原型必须验证平台实际支持的原生授权/回调或其他受支持访问方式，并验证平台登录过期、应用令牌过期、注销、上传下载和重定向。未验证前不承诺“App 输入 Sites URL 即可用”。

- 不提取用户浏览器 Cookie，不在 App 内嵌平台服务绕过令牌，不将应用 Bearer 转发至外部重定向地址。
- 不通过关闭 owner-private、放宽 CORS 到任意来源或伪造身份头解决接入问题。
- 若平台没有可用的原生路径，保留 Web 私有测试；说明证据与替代的独立私有 API 入口方案，取得用户确认后再调整部署。
- 额外主机、第三方隧道、收费服务、网络安全设置和持续访问授权均单独确认。

## 5. 应用认证提案：可撤销设备会话

现有 `api/auth.py` 校验全局密码 Bearer，未提供设备令牌签发/撤销。以下是**拟新增能力**，不能写成现有可调用 API。

建议流程：受信任 HTTPS 连接 → 用户手动输入现有应用密码 → 服务端验证并签发随机设备会话 → 客户端安全保存设备凭据，丢弃输入密码。平台入口闸门须先通过。

- 设备会话服务提供“创建会话、刷新会话、列出我的设备、撤销单设备、撤销全部设备”操作；路径和请求模型在后续契约设计中冻结。
- 推荐短期 access token 配合轮换 refresh token；初始提议 access 15 分钟、refresh 最长 30 天，属于待审核默认值，不是已启用策略。
- 服务端只保存令牌摘要、会话 ID、到期/撤销/使用时间及用户可识别的设备名称；撤销后不再接受该会话，包括尚未自然过期的 access token。
- 刷新令牌轮换、重用检测、并发刷新单飞及丢失响应恢复必须一起设计，避免正常弱网误撤销或旧令牌无限有效。
- 登录限速、失败不泄露凭据、返回 no-store；日志不含密码、令牌或完整授权头。
- Android 使用系统安全存储，iPad 使用 Keychain，鸿蒙采用经验证的平台安全凭据能力；不落到普通偏好文件、项目 ZIP 或共享源码。
- Web 也应迁移到会话机制；具体采用 HttpOnly 会话 Cookie 或内存令牌的方案须结合现有 CSRF/Origin 检查审查，不继续持久存全局密码作为长期目标。
- 兼容旧 Web 的迁移窗口有明确截止与回退方案；更改全局密码、丢失设备与服务器恢复后会话失效行为须有测试。
- 模型密钥、Google profile 和服务端加密密钥始终留在服务端；移动客户端不成为这些凭据的配置分发渠道。

此方案是单用户多设备，不附带多租户、团队权限或企业 SSO 承诺；实施新凭据生成或认证配置变更前核对具体授权。

## 6. 契约与客户端分层

服务端是事实来源。现有 `/api/personal` 端点见 [API_CONTRACTS.md](API_CONTRACTS.md)，保持兼容；契约版本化不意味着立即把全部端点改为 `/v1`。

计划建立 `contracts/v1/`：固定 OpenAPI 快照、变更策略和公开合成 fixtures。接口以运行应用实际生成的 schema 为基准；手写文档不能覆盖真实行为。

- 明确 notebook/source/version/evidence/job/turn 身份、错误码、字段空值、枚举和时间格式；所有端从相同 fixtures 校验解析。
- 新增字段优先兼容；破坏性变更必须提升契约版本并给出客户端兼容窗口。服务能力状态须可检测，不靠客户端版本猜测 Google 是否可用。
- 公共客户端 SDK 不含浏览器全局对象、硬编码服务器 URL、密码或 Google 内部调用；生成文件与手写适配代码分开管理。
- RN 可以使用生成的 TypeScript 类型；ArkTS 从相同 schema/fixtures 验证自己的 DTO，不假设 npm 包或普通 TS 代码天然兼容。
- 任务采用稳定 job ID、幂等键和已有提交状态；断网/离开页面后恢复原任务，未知提交先核对，不能盲目重发创建或生成。
- 已有 turn events 表示持久状态，不宣称逐 token 流式输出；取消本地等待与远端真正取消必须分开显示。
- 原件/成果下载只接受受保护的应用资源路径；跨域跳转不携带 Bearer，文件名净化、限制/哈希验证与服务端保持一致。

移动端分为领域状态、API transport、原生界面、平台 adapters。平台接口边界如下：

| Adapter | 职责与共同约束 |
|---|---|
| 连接与认证 | 校验目标 HTTPS、处理受支持的平台登录、单飞刷新、401/撤销；禁止凭据跨 host |
| 安全存储 | 保存/删除设备会话，锁屏与系统备份策略明确，不保存全局应用密码 |
| 文件选择与上传 | 系统选择器、URI/权限生命周期、大小限制、取消与幂等；不要求读取所有文件权限 |
| 下载与分享 | 受保护下载、临时文件清理、系统保存/分享，不使用 DOM anchor |
| PDF/引用 | 物理页与证据身份准确、历史版本可辨、不可定位时回退原文并解释 |
| 任务与生命周期 | 前后台恢复、网络变化、轮询节流、状态重查；不承诺后台常驻执行 |
| 可访问性与导航 | 返回栈、字体缩放、读屏焦点、键盘/指针和横竖屏适配 |

## 7. 首版在线 MVP 与各端体验

首版包含连接与登录、工作台列表、资料上传/版本阅读、引用定位、问答及追问、笔记保存、任务恢复、现有音频播放/下载、项目导出/导入。后台能力受阻时，各端同样诚实呈现。

导入/导出需要完整文件链路验收；如果某平台暂时不支持大文件可靠保存，该平台标记功能受阻，不以“分享按钮已出现”作为完成。

**不包含：** 离线编辑队列、多设备冲突自动合并、端侧模型、后台无限运行或各端各自直连 Google。离线显示清楚的未连接状态，不自动排队发送写请求。未提交的笔记/问题草稿采用受保护的本地暂存，应用被系统回收后可以恢复；它不是跨设备离线同步，注销前须明确提示并处理未提交草稿。持久只读资料缓存以后单独设计，非首版承诺。

跨端草稿并发、笔记保存版本校验、冲突提示需要统一契约：不能静默用迟到请求覆盖另一个设备的新内容。若现有 API 不具备条件写入，作为契约阶段缺口解决后再开放多设备编辑。

- Android：符合系统返回行为、文件选择与权限拒绝路径、触控尺寸、手机窄屏；前后台切换不丢任务身份。
- iPadOS：侧栏/主内容分栏、横屏与分屏、外接键盘和指针；不是把手机页面等比例放大。
- 鸿蒙 6：ArkUI 导航与文件/权限习惯，独立验证 PDF、下载、生命周期与安全存储；不假设可运行 Android APK。
- Web：保留完整流程作为稳定基线；移动端不应因共享接口改动而破坏现有浏览器会话和下载。

PM 红队每端走一次“首次连接 → 导入 → 提问 → 看引用 → 记笔记 → 导出”真实学习流程，并加入密码错误、空资料、离线、权限拒绝、大字体、重复点击、取消结果不明、后台回来和服务休眠。

## 8. 数据持久化、导出与完整迁移

| 数据 | 容器持久位置/归属 | 迁移原则 |
|---|---|---|
| personal 资料与状态 | `/app/data/personal`，`STUDY_WORKBENCH_DATA_DIR` | API/worker 同一受保护本地卷 |
| 上游 uploads/checkpoints/podcasts 等 | `/app/data/upstream-data`，`OPEN_NOTEBOOK_DATA_DIR` | 纳入完整部署备份，不只复制 personal |
| SurrealDB | 独立 DB 卷 | 使用与运行版本匹配的备份/恢复方式 |
| 加密密钥及其他秘密 | 镜像外秘密文件/配置 | 独立安全保存，不在项目 ZIP/仓库 |
| Google 登录 profile | 独立应用所有目录，最小挂载 | 不在镜像/项目导出；是否迁移另行授权 |

项目 portable ZIP 是学习项目的可验证导出，不是整台服务器备份。它不能替代 DB、上游数据、部署配置与加密密钥；丢失密钥会使已有加密配置无法恢复。

完整迁移：停止新写入 → 排空或记录未完成任务 → 停止 API/worker/DB 写入 → 一致备份各卷 → 独立保存秘密 → 在新 Compose 项目恢复 → 校验计数/哈希、SQLite、解密、引用和任务不误重放 → 切换入口。

先用合成数据演练并保留旧实例可回退；回退必须匹配旧代码与数据快照，不能在已升级数据上盲目降级镜像。备份至少有一份可从 dot 工作区外取回。

## 9. 源码归属、Git 基线和并行分支

**开工作树前先规范基线。** 审计源分支与私有快照文件差异、README/manifest 及排除规则，确定私有仓库中的规范集成基线，保留上游归属、许可证和源提交来源记录。

不得盲目 `git push origin`，不得向 `lfnovo/open-notebook` 推送；不得将两个不同历史假装为同一个提交，或通过强推稳定 main 掩盖差异。私有快照发布器在迁移方案验证前继续使用；更换发布方式必须保留秘密扫描和来源映射。

以下是拟定职责，具体分支只在阶段入口满足后建立：

```text
经审计的私有基线 → integration/multiclient-v1
  ├─ feat/docker-deployment ───────────────┐
  └─ feat/api-contracts-v1 → feat/device-auth
                 契约/认证/入口闸门冻结  │
                   ├─ feat/mobile-core ──┤
                   │    ├─ feat/android-client
                   │    └─ feat/ipados-client
                   └─ feat/harmonyos6-client
                                ↓ 分批集成与每端验收
                         私有 main / 各端版本标签
```

| 目录（拟新增者为设计路径） | 唯一主责/写入约束 |
|---|---|
| `contracts/v1/` | 契约负责人；其他端通过评审提变更，不各自改 schema |
| `packages/api-client/` | 公共无平台 transport/类型负责人；不引入 DOM 或平台凭据 |
| `clients/mobile/src/` | RN 共享核心负责人；Android/iPad 分支不复制或分叉这套业务 |
| `clients/mobile/android/`、`clients/mobile/src/platform/android/` | Android 分支负责原生构建与适配 |
| `clients/mobile/ios/`、`clients/mobile/src/platform/ios/` | iPadOS 分支负责原生构建与适配 |
| `clients/harmonyos/` | 鸿蒙分支；独立 ArkTS/ArkUI 与 DTO 一致性测试 |
| `deploy/v1/`、`scripts/v1/container_check.py`、`tests/test_v1_container_contract.py` | 部署分支；不同时修改移动端业务 |
| `api/`、`open_notebook/`、`frontend/` | 现有服务/Web 负责人；跨目录接口改动先协调 |

每个并行分支独立 worktree、测试资源与明确文件边界；共享核心变更先回集成分支再同步。远端平台分支必须有真实有界工作和可读进度，不能只开空分支充作交付。

小批次 PR 集成、契约兼容检查、冲突人工审查；不强推别人的分支、不重写稳定 main。不在本设计阶段创建分支或发布客户端包。

## 10. 阶段路线、交付证据与停止条件

| 阶段 | 工作与并行关系 | 退出标准 |
|---|---|---|
| M0 设计审阅 | 本规格、设备/工具链清单、私有 Git 基线方案 | 用户接受设计；未定策略清楚标注，随后产出详细实施计划 |
| M1 基础闸门 | Docker 静态方案与认证/契约设计可并行；研究 Sites 原生连接 | 基线可追溯、秘密排除通过、受支持入口原型有结果；不能用猜测放行 |
| M2 可迁移服务 | 在获准 Docker 主机真实构建四服务，迁移恢复演练；完成契约/设备认证 | Web 回归、负向访问、撤销、任务、备份恢复通过；稳定契约可供客户端使用 |
| M3 共享移动核心 | RN 共同在线流程；鸿蒙可按冻结协议并行开发 | 合成 fixtures/错误/幂等/状态恢复通过；共同接口不再各端漂移 |
| M4 平台适配 | Android/iPadOS 原生目录分别并行；鸿蒙独立适配 | 每端分别完成编译、模拟器、真机、签名包证据，不合并成一个绿灯 |
| M5 私人试用 | 各端 PM 红队、安全回归、迁移说明；先交付已过门槛的端 | 用户真实学习流程成功；其余端明确受阻原因与下一步 |

真实模型、Google 登录/导入/写入/音频与严格会话隔离继续按照 [GAP_CLOSURE_PLAN](GAP_CLOSURE_PLAN.md) 独立推进；可在无共享文件冲突时并行，不等待所有客户端完成才做。

原 V1 的 Google 默认问答要求未因多端改变；如先交付独立模型试用版，需用户明确接受并标注偏离。严格隔离不能证实时继续 fail-closed，不删除历史来伪造隔离。

应用自己的 Google 可见登录需专用 profile、受控登录流程和真实只读验证；当前登录占位状态不能被客户端包装成成功。可见浏览器宿主/依赖另行验证，不默认塞进普通 API 容器或读取用户浏览器 Cookie。

## 11. 验收矩阵、工具链与权限

每端状态独立记录为：未开始 / 源码完成 / 静态或单测通过 / 编译通过 / 模拟器通过 / 真机通过 / 已签名可安装 / 受阻；记录代码、契约、OS、SDK、设备与测试时间。

- Docker：当前 dot 仅可做静态检查；真正 build/Compose、卷恢复、非 root、网络隔离与 worker 运行必须在具备能力且获准的宿主取得证据。
- Android：JDK/Android SDK 与目标 API 以设备和 RN 支持矩阵冻结；debug APK 可用于开发，release 签名密钥独立保管，不能提交仓库。
- iPadOS：原生编译/模拟器需要兼容 macOS 与 Xcode；当前 Linux 不满足。个人 Apple 账号可能支持有限真机测试，分发/TestFlight 等另核对资格，不能一概声称测试必须付费。
- 鸿蒙 6：确认匹配的 DevEco Studio、SDK、可用宿主、模拟器/真机与签名流程后才能承诺包；当前 Linux 构建能力未验证，不假定与 Android 相同。
- 真实设备清单、系统版本、包名、签名身份、证书与分发方式在 M0/M1 收集确认；没有设备时模拟器证据不得替代真机。
- 不安装新工具链、购买账号、启用收费 CI、上传签名私钥或发布应用商店包，除非对应执行得到授权；设计审阅不等于支付或发行授权。
- 全端验证未登录拒绝、设备撤销、跨 host 凭据不泄露、Origin 写保护、权限最小化、私有文件不进日志/缓存备份。
- 全端验证引用版本/页码、草稿不被迟到结果覆盖、未知提交不重复、取消语义、大文件与权限拒绝；iPad 加分屏/键盘，手机加返回、系统回收后草稿恢复与生命周期。

**全局发布硬门槛：** 实际受保护入口可用、认证及数据安全通过、任务与恢复可靠、该版本承诺的真实模型/Google 能力有真实证据。漂亮界面、模拟测试或已签名包均不能替代这些门槛。
