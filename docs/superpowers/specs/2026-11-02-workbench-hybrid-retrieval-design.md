# StudyWorkbench evidence-native hybrid retrieval design

Proposed repository path: `docs/superpowers/specs/2026-11-02-workbench-hybrid-retrieval-design.md`.
Status: selected direction with independently reviewed engineering design; no product implementation or runtime acceptance claimed. Baseline: private `Zhou-chu/study-workbench`, `fix/audit-followup-20261022`, SHA `df94d8c18bfbae217aea5c9283b7a24d38844d24`. Reconcile branch changes before implementation.

## Decision and scope
The user explicitly selected reuse of existing infrastructure after being offered existing SurrealDB/model configuration versus txtai, and asked to continue audit/improvement and push progress. They did **not** select an embedding model, endpoint, dimensions, cloud spend, or automatic indexing. All operational defaults below are engineering proposals, not their preferences or authorization for real provider calls.

Add semantic recall to the independent/local workbench search and question path without replacing the authoritative evidence chain. Keep lexical search usable without any model. Success means correctly scoped semantic candidates can augment lexical candidates while citations retain their immutable source version, extraction, evidence ID, quote hash and locator. Indexing, failure, fallback and provider data flow must be visible.

Non-goals: txtai/Faiss/SQLite, another vector DB or RAG framework; legacy source/notes vector bridging; graph RAG/reranking/agents; automatic OCR, fetching models, importing remote KBs, changing NotebookLM capability, automatic reindex on upload or configuration change, exhaustive summaries. Outline continues its existing bounded overview path and makes no query-embedding call.

## Approaches
1. **Selected: evidence-native derived vectors in existing SurrealDB; existing Esperanto model provisioning.** Smallest coherent addition preserving evidence identity. Initial exact cosine ranking of bounded, DB-prefiltered vectors avoids ANN post-filter leakage and new dimension-specific index DDL. It reuses storage/model infrastructure, not the unsafe semantics of old search.
2. Reuse legacy `fn::vector_search` and map its source hits back to evidence: rejected. Legacy empty notebook scope is global, records lack immutable workbench extraction identity, and mapping cannot restore pre-retrieval scope guarantees.
3. Embed txtai: rejected for this increment. Its independent index lifecycle and dependencies duplicate infrastructure. LlamaIndex/LightRAG likewise add abstractions or graph extraction not needed here. These are alternatives, not dependencies.

## Pinned observations and affected seams
- `api/evidence_service.py`: `retrieve(query, version_ids, limit=12)` performs lexical scoring; empty scope fails; max selected sources defaults 20; ready/partial only; `list_evidence` and `validate_citation` preserve archive/provenance distinctions.
- `api/routers/evidence.py`: `/personal/search` currently accepts query + version IDs and returns hits; unlike grounded chat it has no explicit notebook field. New hybrid requests require notebook identity and server validation; preserve old lexical clients.
- `open_notebook/graphs/grounded_chat.py`: independent/local only; no hits skips generation; bounded prompt and supplied-evidence citation validation remain authoritative.

- `open_notebook/ai/models.py`: `model_manager.get_model(model_id)` provides configured Esperanto models. `open_notebook/utils/embedding.py` currently resolves mutable defaults and retries up to three times; calling it unchanged does not pin model identity or guarantee non-replay.
- `commands/evidence_commands.py`, `commands/__init__.py`, `api/personal_service.py`: reuse worker registration, durable jobs and reconciliation conventions, not extraction's automatic retry policy for paid embedding calls.
- Migrations currently end at 30; proposed 31 must be renumbered if the branch advances. Both sync/async migration registries must include it if both remain supported.

## Safety invariants
- Empty scope is deny, never global. Validate every requested version's existence, notebook membership and ready/partial extraction **before any evidence content read, vector retrieval or model provisioning/call**. One invalid/not-ready version fails the entire request; never silently shrink the scope.
- Public profile/status responses and logs contain no secrets, text, query, vectors or provider error bodies. URLs displayed for data destination omit credentials/query/fragment. Do not classify an endpoint as on-device merely because it is called “local.”
- Canonical evidence is authority. Derived rows contain no quote/title/locator copy. Fetch selected immutable extraction membership explicitly; before prompt/response, reread canonical evidence and validate physical ID, version, extraction, hash and current scope. Corrupt/out-of-scope rows fail closed, not as normal degradation.
- A newer version does not rewrite older evidence. Explicit selection of a retained old version is allowed; current extraction identity for that version must match the captured retrieval snapshot. Reparse changes extraction and invalidates that version's current semantic readiness, without deleting historical citations.
- Deletion/cancellation prevents new dispatches and new commits, not reversal of bytes already sent. Never claim remote cancellation stopped billing or erased provider data.
- Upload, extraction, workspace/status polling, index preview, lexical search and outline do not embed. Hybrid search is explicit per request and its UI is submit-only, not on each keystroke.

## Components and interfaces
Create `open_notebook/domain/evidence_retrieval.py` for immutable Pydantic/dataclass contracts:
- `EmbeddingProfile`: `profile_id`, existing `model_id`, provider/model name, configured revision/deployment identity, sanitized endpoint fingerprint, credential-binding ID (not key), dimension, document/query prefixes, preprocessing revision `evidence-identity-v1`, max_input_bytes, cosine_min_score, configuration fingerprint. Require complete explicit profile; missing/unknown dimension or revision means unavailable, not a paid probe. Fingerprint all vector-affecting fields; never put key material in it. Provider aliases cannot prove immutable weights: an operator-pinned revision/deployment and deliberate profile rotation are required; document that external silent alias mutation is undetectable.
- `ScopeSnapshot`: notebook ID plus sorted `(source_version_id, extraction_id, manifest_hash, scope_epoch)` entries, validated from canonical metadata. `manifest_hash` hashes ordered evidence IDs + quote hashes. `scope_epoch` is a retrieval revocation generation maintained by the new repository.
- `RetrievalResult`: `hits`, `requested_method` (`lexical`/`hybrid`), `retrieval_method` (`lexical`/`hybrid`/`lexical_fallback`), `fallback_reason`, `profile_id`, `indexed_version_count`, `selected_version_count`, `warnings`. Metadata exists even for zero hits. Scores are ranking values, not confidence.

Create `open_notebook/ai/evidence_embeddings.py`: `resolve_profile(profile_id)`, `embed_documents(profile, texts)` and `embed_query(profile, query)`. Resolve only the pinned existing model ID, enforce type/config identity before each call, reuse existing provider URL/credential validation, no default-model substitution. Add an explicit-model/no-retry entry point to existing utility if useful, preserving classic callers' behavior. Do not invoke unchanged default-resolving helper. Enforce input byte budget including prefixes, timeout 30 seconds, batch size 16, concurrency 1 per worker. Reject overflow rather than truncate or secretly rechunk evidence. Validate exact response count, finite nonzero vectors and configured dimensions, normalize for cosine. Disable SDK/provider retries where supported; providers with uncontrollable automatic retries are not enabled for this path until their behavior is disclosed and validated. Timeout is outcome-unknown; no application replay.

Create `open_notebook/database/evidence_embedding_repository.py`: bound-value queries over new dedicated tables, without using global `PersonalStore.list()`. Store profiles, per-version/namespace manifests and vector rows in SurrealDB. Logical namespace = profile fingerprint + dimension + preprocessing revision. Vector row key = hash(namespace, version, extraction, evidence ID, quote hash, index attempt); row fields contain these identities, notebook ID and normalized vector only. A single atomic manifest pointer publishes an attempt after all expected vectors are stored and checked; staging rows are invisible. Fetch rows **with notebook + selected version/extraction + namespace + committed attempt predicates in the DB**, returning at most 5,001 rows; no global ANN candidates, no content hydration from vector rows. Composite B-tree indexes support scope predicates; no HNSW/MTREE in this first increment. Validate returned row identities again in application.

Create `api/evidence_retrieval.py` with `EvidenceRetrievalService.retrieve(query, notebook_id, version_ids, *, mode='lexical', profile_id=None, limit=12) -> RetrievalResult`. Keep existing `EvidenceService.retrieve()` as lexical compatibility boundary; share its lexical scorer rather than change classic callers. New entry point performs preflight across all metadata, then canonical reads. Request limit 1..100, query <=50,000 characters and configured embedding byte limit, source count <= existing 20-source limit. Hard semantic scan cap 5,000 rows across selected versions and `dimension <= 4096`; over cap falls back for the **whole** scope, never first-N vectors. Exact cosine in bounded batches uses existing numpy; lexical ranking remains exact current term algorithm.

## Indexing and explicit consent
Profiles are deployment configuration referencing existing models, **not new credentials**. Suggested deployment variables: feature flag `STUDY_WORKBENCH_HYBRID_ENABLED=false` and profile file setting `STUDY_WORKBENCH_EMBEDDING_PROFILES`; no model/endpoint default is installed. A profile includes its explicit cosine threshold; there is no universal threshold promised to improve all providers.

New authenticated endpoints in `api/routers/evidence.py`:
- `GET /personal/notebooks/{notebook_id}/semantic-index?source_version_ids=...`: scope/status/profile descriptors only, no model construction/network call.
- `POST /personal/notebooks/{notebook_id}/semantic-index/preview`: exact selected versions + profile; validates scope, returns preview token/hash, extraction identities, evidence count, UTF-8 byte count (not fabricated cost), provider/model/data destination and local-vs-remote uncertainty. No provider call. Maximum 20 versions and 5,000 evidence rows; overflow requires a smaller explicit selection, not truncation.
- `POST /personal/notebooks/{notebook_id}/semantic-index`: body `{source_version_ids, profile_id, preview_hash, acknowledge_external_processing, idempotency_key, retry_of_job_id: string|null = null, acknowledge_duplicate_embedding_cost: boolean = false}`. Fresh preflight must match preview/config before jobs are created; remote/unknown destination requires affirmative acknowledgment. Explicit action covers document embedding only; using hybrid search separately discloses query embedding. One durable job per version, grouped receipt; no automatic ingestion hook. Missing config/auth gives actionable failure before queueing.

`api/evidence_indexing.py` orchestrates durable preview/job receipts and run; `commands/evidence_commands.py` registers `index_evidence` with max_attempts=1. Idempotency binds notebook+versions+extractions+profile+preview+intent. A duplicate exact key returns same receipt; conflict returns conflict; uncertain queue submission is `submission_unknown`, reconciled against existing worker receipt and never automatically resubmitted. Use project's existing dispatch ownership conventions, not a new alternate queue.

Lifecycle: `queued -> running -> succeeded | failed | submission_unknown | cancelled_local`. Persist stage (`preflight`, `embedding`, `publishing`), completed/total evidence and structured sanitized error code. Progress increments only for acknowledged stored batches. Before every batch, recheck job cancellation, canonical scope epoch, extraction and profile identity. Record dispatch-started before provider invocation. On process death with dispatch-started but no recorded response, mark outcome unknown during reconciliation and require an explicit new retry attempt acknowledging possible duplicate provider cost. First increment has no cross-attempt batch resume: an explicitly confirmed retry rebuilds the whole version under a new attempt ID, after warning that even acknowledged prior batches will be embedded again and may incur duplicate cost. Do not silently replay any batch. Success requires count/hash-complete manifest atomically published, not merely queue acknowledgment or returned provider vectors.

Index status is independent from extraction status: `not_indexed`, `indexing`, `ready`, `failed`, `stale`, `unknown`; ready extraction still supports lexical while indexing. No partially indexed version advertised ready. A failed rebuild may retain the last complete compatible manifest if its scope/extraction/profile still match; report last-good vs failed attempt separately.

Deletion/reparse/source-removal hooks bump scope epoch under the existing project commit barrier; publish uses scope epoch compare-and-set so stale workers cannot resurrect usable rows. Cancellation fences only its index attempt (attempt generation/cancel flag), not the authorization-wide version scope epoch. Publish must check both scope epoch and the uncancelled attempt fence. Cancelling a rebuild does not revoke a prior complete compatible manifest. Tombstone/epoch commit happens before cleanup; physical vector deletion is retryable local housekeeping. Version deletion and notebook deletion must call invalidation even when cleanup fails; retrieval also checks authoritative existence. Old vectors in another namespace never match the query namespace. Never change originals/historical evidence during index cleanup. Do not hold project locks over provider calls; authorization linearizes at dispatch-started under the barrier. A later revocation cannot unsend an in-flight request; it blocks publication and future requests.

## Retrieval and ranking
1. Validate all selected metadata and caller notebook scope; reject empty scope before model/profile work. Capture scope/extraction epoch snapshot.
2. Produce lexical candidates only from that validated scope. For requested lexical, return lexical metadata and zero embedding calls.
3. Hybrid is eligible only if feature enabled, explicit profile valid, destination disclosure accepted in UI/request, **every** selected version has a complete compatible index, and total rows <=5,000. Otherwise return lexical_fallback with a stable reason (`FEATURE_DISABLED`, `PROFILE_UNAVAILABLE`, `INDEX_NOT_READY`, `INDEX_STALE`, `SCOPE_TOO_LARGE`, `QUERY_TOO_LONG`). No query embedding on these preflight failures. Never auto-index or select another provider.
4. Query embedding runs once, after validation. Ordinary unavailable/timeout/provider failures return lexical_fallback (`EMBEDDING_UNAVAILABLE` or `EMBEDDING_OUTCOME_UNKNOWN`); no auto-retry, with uncertainty disclosed. Database unreadability that prevents scope validation is an error, not fallback. Configuration change that invalidates the disclosed fingerprint or destination descriptor rejects with EMBEDDING_DISCLOSURE_STALE before provisioning/call; it must not silently select another provider or treat stale consent as ordinary fallback. Integrity/authorization failures remain errors.
5. Score only prefiltered vectors. Semantic list contains rows with cosine >= profile.cosine_min_score, descending cosine then evidence ID. Take top 48 each for lexical and semantic; fuse union via reciprocal-rank fusion `sum(1/(60+rank))`, one-based ranks, deduplicate evidence IDs, stable tie by ID; final limit defaults 12. A method with no candidates contributes nothing; do not manufacture hits simply because vectors exist. Metadata says hybrid when semantic ran successfully even if it added no hits; per-hit channels show lexical/semantic/both.
6. Reread canonical candidates through evidence service, verify extraction manifest, notebook/version/epoch scope and hash; keep restored archive `unverified` and derived provenance unchanged. Invalid/out-of-scope integrity aborts; never pass those quotes to model. Missing/reparsed/deleted scope aborts with `SCOPE_CHANGED` and asks for explicit retry. Immediately before generation recheck captured snapshot; no hidden scope expansion. Existing citation validator still checks model citations against supplied hit IDs and exact quotes; semantic score never upgrades validity.
7. Return/persist complete retrieval metadata on search result and turn, including zero-hit result. No hit still means no **generation** call (query embedding may have occurred); UI distinguishes these. Outline remains selected_overview. No-hit wording means “this retrieval found no supporting excerpts,” never “the material contains no answer.”

### Contract clarifications for implementation
`ScopeSnapshot` validation also requires the notebook still exists and each source remains referenced by it; retained version metadata alone is not active membership. Hook invalidation in `open_notebook/domain/notebook.py` source/notebook deletion and reference removal path `api/routers/notebooks.py`, as well as evidence reparse publication, so classic deletion entry points cannot leave workbench semantic access live. Retained historical citation display is not a new search authorization. A notebook/source removal during retrieval produces SCOPE_CHANGED.

Hybrid search adds `notebook_id`, `retrieval_mode`, `embedding_profile_id`, `acknowledge_query_processing` to `/personal/search`; hybrid turns add the latter three to `TurnRequest`. Default mode is lexical; hybrid requires acknowledgment for remote/unknown destinations. These fields participate in request hashing/idempotency and the request-generation guard; changing profile/mode is never a silent retry of an old turn. Old lexical search requests retain current compatibility; new workbench requests always send notebook ID. Retrieval service receives `acknowledge_query_processing: bool = False` explicitly. Profile/status/preview configuration reads must not construct Esperanto models (which can perform URL validation); only the authorized call boundary does so.

The implementation must enforce a memory bound **before returning vectors from DB**: total selected vector elements <=2,000,000 in addition to <=5,000 rows and dimension <=4096. Exceeding either is whole-scope lexical_fallback, with zero query embedding calls. These conservative engineering limits are not measured performance claims. Profile input byte limits and cosine threshold require explicit deployment values; out-of-range thresholds outside [-1,1] and nonpositive limits reject the profile. No download or provider call discovers them.

### Builder correction: disclosure identity is a request contract
An acknowledgment boolean and profile ID alone do not authorize a rotated endpoint. Every hybrid search/turn request MUST include `disclosed_profile_fingerprint` and `destination_descriptor_version` captured when the user saw the disclosure, alongside `acknowledge_query_processing`. The server compares both against current resolved nonsecret configuration at acceptance and immediately before provider dispatch, **before model provisioning or URL/network work**. A mismatch is `EMBEDDING_DISCLOSURE_STALE` and rejects the hybrid operation (no silent fallback that accepts a new provider, zero bytes/calls); the UI requests fresh disclosure. The fingerprint includes provider/model/revision/dimension/preprocessing and destination identity; descriptor version changes if data-flow disclosure changes. Bind both fields into turn request hash/idempotency, indexing intent where relevant, and frontend request generation. Already-queued turns retain their original disclosure identity, never read a new UI acknowledgment. Configuration rotation between final check and invocation uses the checked frozen configuration object, not another mutable lookup; if the existing ModelManager cannot provision that frozen identity, extend its explicit-model boundary additively rather than call a fresh mutable resolver.

Add mandatory test: acknowledge profile A, rotate the same profile ID to endpoint/model B, submit or dispatch an existing queued request with A fingerprint => `EMBEDDING_DISCLOSURE_STALE`, zero provider/model-provisioning calls, fresh UI disclosure required. Same-dimensional changes are not an exception. Embedding credential secret rotation alone need not change semantic namespace if destination/model remains identical, but mutable credential binding/config must still match the frozen allowed destination.

Builder decisions incorporated: query-disclosure fingerprint binding; attempt-local cancellation independent from scope revocation; full-version explicit retries with honest duplicate-work/cost warning instead of cross-attempt resume. These are engineering proposals within infrastructure reuse, not new user settings.

### Explicit retry and disclosure schemas
`QueryEmbeddingDisclosure` contains `disclosed_profile_fingerprint: string`, `destination_descriptor_version: string`, and `acknowledge_query_processing: boolean`; both SearchRequest and TurnRequest carry these fields directly and require nonempty fingerprint/version for hybrid. They are persisted into request identity and queued dispatch, not inferred later from current profile settings.

`IndexRequest.retry_of_job_id` defaults to null and `acknowledge_duplicate_embedding_cost` defaults to false. An explicit retry supplies a same-notebook/version/profile prior failed/unknown/cancelled job ID, a fresh idempotency key, a current preview and affirmative duplicate-cost acknowledgment. False/missing acknowledgment rejects a retry before queueing/provider calls. Cross-notebook or mismatched retry references reject. Retrying never replaces the old job identity/history or resumes its batches. Under the commit barrier, fence the referenced old attempt before activating the new attempt so a late uncertain worker cannot publish; preserve its historical receipt. The duplicate-cost flag alone cannot authorize automatic replay. Initial builds omit retry_of_job_id.

Execution verification uses only the repository-supported offline backend runner with the prepared tiktoken cache, and `npm run test` / `npm run test:unit -- <paths>` frontend scripts; see plan for exact commands. No ambient credentials or real-service configuration enter offline tests. User-directed continued autonomy does not require another optional architecture-choice question.
