# StudyWorkbench 产品体验门禁与修复范围

## 目标与授权

以学习者长期阅读/问答/笔记工作流为中心，而非营销页或工程控制台。用户于 2026-10-28 明确要求自主审查、制定计划、实施修复并复测至产品经理门禁通过，无需逐项设计确认。授权不包含真实笔记迁移、生产部署、main 合并、新凭据或绕过执行限制。

一句话任务：**选定资料，阅读并追溯证据，提问，将有出处的结论沉淀为笔记。** 保留 Sources / 阅读与问答 / Notes 三个任务区域、Quiet Green 语义设计和独立设置；不用 hero、图片数量、动效数量或第三方作者的颜色偏好评价学习应用。

## 确认问题及决定

### P1：笔记草稿替换缺乏明确同意

New/Edit 直接替换文本并重置冲突状态。生成提纲的完成保护只检查请求后的编辑代次，未保护请求开始前已存在、随后未改动的草稿。

决定：对实际会丢弃草稿的 New/Edit/Outline 建立统一的、会话和编辑代次绑定的确认入口。普通新建空白/无修改的已存笔记不增加确认。确认说明具体动作及未保存修改会被替换；确认 Edit/New 后使编辑器可见并将焦点移入，避免在长笔记下操作后找不到编辑位置；取消/ESC 保留完整文本、标题、引用、scope、base revision 与审核信息。确认本身不自动保存或发重试。提纲在确认前绝不提交；确认后也保留旧草稿至可信完成，既有 owner/session/revision 保护继续生效。

保存正在进行，或当前笔记存在 `!canRetryNoteWrite(noteProblem)` 的未知/冲突/拒绝状态时，不允许通过 New/Edit/Outline 清空相关审查证据；显示原因及现有比较入口。局部阻止不影响阅读/提问或其他已存在的只读恢复。已证明未发送/认证拒绝依旧按原规则处理。若确认打开后草稿、editor session、受保护保存状态或目标改变，旧确认失效并保留草稿，不能凭旧确认替换新内容。

### P1/P2：资料范围不透明与搜索结果陈旧

问题框仅显示选中数量，无法判断将使用哪个引擎及本地/远程来源；阅读与选源的关键区别藏在设置里。搜索依赖当前闭包，却没有为结果绑定已提交查询和选定版本，换范围或输入后旧结果仍可点击。

决定：在问题输入旁显示紧凑的引擎、来源类型、选中数量与“更改”入口；保留未知/不支持状态，不能将其显示为默认引擎。资料区明确“阅读不会自动改变问答范围”。不搬回大块配置面板，不额外自动写 selection。

证据检索作为同 notebook 内独立只读动作：同步捕获查询与本地版本数组，结果/错误/空状态只属于其捕获的请求。查询文字、选源范围/来源、notebook 或隐私上下文变化后，不呈现或激活不匹配的旧结果；旧 pending 响应不能复活。读取位置变化不使同范围结果失效。查询前、加载、成功零结果、失败、需重新搜索各有明确反馈；不为输入/范围变化自动请求，不伪造取消了服务端请求。Enter 提交遵守 IME composing，重复提交同步防护。

### P2：阅读筛选与可见数据的保存/刷新反馈

来源/引用切换时，文内筛选不得暗中沿用旧文档条件并把零匹配说成没有提取文本。按来源/引用身份重置筛选，区分无文本与无匹配，提供显式清除；不改变 locator、核验或当前选源。

已有 workspace 数据刷新失败时保留内容和草稿，显示持久但紧凑的“刷新失败，显示上次数据”与只读重查。不能用空列表替代旧内容，不能重放上传/保存/生成。

当前 selection 草稿与最后持久化状态分开。保持已有按 notebook 的 mutation scope 串行，不自动重试；对最新变更显示保存中/未确认保存的持久反馈和显式重试最新支持的完整选择。晚到旧失败不得把已成功的新选择标错，旧成功也不能清掉新失败。保留未知字段投影和认证/隐私限制，不把“未确认保存”说成“服务器肯定未写入”。读取位置变化也受持久化反馈覆盖，但不改变问答范围。远程模式明确本地勾选不用于当前远程问答，不能偷偷切回本地。

### P1/P2：可读性、触控与长内容韧性

暗色 primary 标签对比度 3.63:1，hover 2.98:1，primary 链接对 card 4.09:1。手机主要控件的源码尺寸是 32/36px，缺少粗指针覆盖。回答与笔记的长引用按钮无宽度约束；两侧 resize 到上限时中央正文可能小于 210px。

决定：保留绿色品牌，将实心操作与文字操作配色配对正确，常规 enabled 文本在真实用途背景上至少 4.5:1，默认/hover 均满足；disabled 单独报告，不冒充 enabled 合规。通过语义 token 修复，审阅所有受影响的消费者，不仅截图上的单个按钮。既有 destructive primitive 的已知暗色白字问题亦纳入相关语义配对，不能留下同类已确认可读性失败。

phone（宽度≤640px）或粗指针下，工作台、关联对话框与移动导航的主要独立控件 hit box 至少44×44 CSS px，保留桌面精细指针密度。44px 是本产品目标，不是宣称所有较小控件违反 WCAG AA。资料工具栏将搜索输入和动作编组，减少无意义纵向堆叠；选源 label 可整体点击且不误触 Read。

引用按钮限制在容器内，可换行/截断的可读来源名优先，完整来源及引用身份仍可访问；显示缩短不得改变 evidence/locator/验证状态。所有引用风险与覆盖提示保留。可调辅助栏必须协调约束，使 desktop 中央有效正文至少340px；更窄可用空间使用现有单区域布局，不牺牲阅读区给两侧栏。导航 selected 状态使用中性状态而非与执行行动相同的实心主按钮，并提供正确 selected/pressed 语义。

## 不实施的替代方案与代价

1. 不整套换肤：当前阅读优先结构成立，换字体/主色/框架会制造回归，不能修复草稿和范围问题。
2. 不仅改文案：草稿与陈旧结果是行为缺陷，需要状态/请求归属测试。
3. 不强制全应用桌面控件44px：保留研究工具密度，扩大 phone/粗指针工作区交互目标；必须真实测量 portal 和焦点。
4. 不扩大为全库RAG、自动网页研究、OCR/PPT解析或持久草稿项目；这些仍是另行产品范围。
5. 当前未证明的 PDF resize 栅格清晰度、长材料双滚动、所有主屏字体加载等列为浏览器待测项目，不将源码猜测当作已确认缺陷。

## 不可回退的工程边界

- 保留 F1 不可变原请求、同步 latch、精确目标/epoch、保守未决 fence、只读 Check 与 editor generation 规则。
- 不新增自动提交/重试、原始异常显示、凭据存储、provider 调用或 Google 写入。
- 不修改 API/数据库/worker 语义，不触碰旧工作区或真实用户文件。
- 所有新文案进入现有共享 workbench locale 对象，英文/简体中文完整；继承该对象的其他 locale 键必须保持齐全，运行 parity/interpolation/type gates。
- 不安装依赖；使用已核验的现成依赖。仅授权私有分支源码/测试/脱敏记录同步，不能合并 main 或部署。
- 不重试被拒绝的 netlink 或降低浏览器隔离。另一个真实测试环境尚待明确批准/验证；未获得时继续安全离线工作，但最终 PM 门禁保持 BLOCKED，不报通过。

## 产品经理门禁矩阵

| 门禁 | 必需证据 |
|---|---|
| G1 草稿保护 | New/Edit/Outline 的取消、确认、双击、晚到保存/生成、确认期间编辑；保留文本/引用/scope/base及未知保存证据 |
| G2 范围与搜索可信 | local/remote/unknown；引擎和数量准确；范围/查询变化与 pending 乱序不显示旧结果；无自动请求；零结果/错误明确 |
| G3 可读性 | 浅/深 action 默认/hover、文字 action、相关 destructive 对比度≥4.5；实际计算 token 链并查看当前双主题像素 |
| G4 响应与触控 | 360/390/768/1024/1280/1440px，zh-CN/en-US；44px目标、无引用引起的横溢出、中央正文≥340px或单区域；真实字体/焦点 |
| G5 完整任务 | 导入测试资料→选择→阅读→提问→追溯引用→保存/重开笔记；失败/中断/返回/重复操作；所有服务只用专用测试资料 |
| G6 工程门禁 | 全前端 tests/types/lint、相关后端离线/static/OpenAPI、官方生产 build 与独立 artifact verify、独立代码/PM复审 |
| G7 交付真实性 | 远端提交/tree/记录回读一致；Taste安装、合成测试、浏览器、服务、部署各自报告，不混为已通过 |

通过条件：G1–G7 对应必需项目都有真实证据且无待修 P1/P2。任何环境阻塞意味着门禁未通过，而不是用可选项或旧截图填补。每次修复只对明确失效项复测，但最终保留跨功能回归及整体审查。
