# Notebook 全新前端与独立 BFF 设计

日期：2026-11-07 UTC
状态：总体设计已获用户确认；按用户随后明确的黑白灰审美与深浅主题要求修订。不是已实现功能或生产部署批准。
适用基线：Zhou-chu/study-workbench，fix/audit-followup-20261022，91a92fa1a9e1bf31dea431afc88efb67c69e1a02。实际部署另有同源 Cookie 补丁，纳入迁移基线。
范围：完整 Web 前端重做，独立 React SPA、独立 BFF，保持 FastAPI、worker、数据与业务安全协议兼容。

## 1. 目标与已作选择

用户认为现界面不好看、难用，要求前后端分离并全部重做前端，体验接近 NotebookLM，同时支持桌面、平板和手机。

已向用户提出两条路线：A 为全新 Next.js 界面并保留其安全代理，B 为独立 React 前端与单独后端适配层。用户明确回复“B”。因此本设计采用 B。这里的“全部重做”覆盖可见页面、信息结构、导航、布局和组件，不等于删除资料、历史、笔记或重新实现已经验证的服务端业务。

成功标准是用户自然完成：进入笔记本 → 添加资料 → 选择问答依据 → 提问与追问 → 点引用核对原文 → 保存成果 → 下次继续。正常流程不需要理解 job ID、版本 ID、embedding、BFF 或内部引擎状态。

技术默认值由设计方提出并随总体设计进入计划：React + TypeScript + Vite；保留 TanStack Query、可复用的无障碍基础与 Markdown/PDF 能力；Node 独立 BFF；同仓库分包；以中文优先打磨、保持现有其他语言支持；视觉以用户明确偏好的黑、白、灰为准，不采用蓝色或其他彩色操作强调。具体灰阶、字重和微交互由视觉验收决定。

## 2. 非目标、反目标和约束

本项目不重写 FastAPI 业务、数据库、任务执行器、NotebookLM 集成、引用身份或 portable 格式；不升级数据库大版本；不加入团队多租户、协同编辑、离线写队列、自动冲突合并或新模型提供方。

不把本次响应式 Web 交付称为原生应用交付。既有 RN Android/iPadOS、ArkTS/ArkUI 鸿蒙方向保持有效，本次产出稳定契约和可复用领域边界，原生编译、签名、私有入口验证仍独立推进。

不可接受的结果：只换颜色却保留表单式操作；为简洁而藏掉错误或未知提交；丢失旧资料/历史；点阅读偷偷改变选源；断线后重复生成/上传/保存；把 AI 派生成果当原始独立证据；用模拟数据声称真实 Google/模型链路可用。

执行阶段先完成当前上传问题的修复与真实回归，再将它作为新前端迁移的既有行为。设计可以同时进行，最终迁移不能把上传修复覆盖。当前运行实例、数据、凭据和入口不因设计选型而变更。

## 3. 新鲜现状与保留资产

2026-11-07 的只读检查确认：

- 已有 Next.js → FastAPI → worker/DB 的进程分层，主要耦合在 Next 路由代理、浏览器 transport、认证恢复和页面业务状态。
- 台式机运行 source-access-cookie 补丁副本；原始 source 的 1,346 个文件已与上述提交核对。补丁让 legacy 浏览器请求在同源时携带入口 Cookie，跨源仍不携带，且保留应用 Bearer。
- 运行配置是 legacy_password，不是 device_sessions。设备会话代码存在不等于启用。
- 公网入口已到达应用登录页；内部页面没有当前已登录像素验收。本文交互问题判断来自固定源码，不冒充实测。
- 现有契约覆盖版本、证据、条件笔记写入、幂等操作、任务状态、SSE 与受保护下载，但 workspace 仍含不透明/历史字段。

应复用或迁移而非重写：已测会话协议和代理策略、操作身份捕获、提交不确定性处理、笔记 revision 冲突处理、上传幂等键、引用定位与历史版本验证、PDF/Markdown 安全渲染、locale 内容与格式化、portable 校验。复用以清楚模块边界和回归验证为准，不是把旧大组件换一个目录。

## 4. Approaches：选项与取舍

### A. 新 Next.js 界面，保留其 BFF

优点是迁移快，原有请求链路改动少。缺点是前端仍需 Node 请求进程，UI 发布和后端适配依然绑在同一应用中。用户没有选择它。

### B. 独立 React SPA + 独立 BFF/API，已选

浏览器只运行静态前端；BFF 独立负责浏览器会话和受限协议转发；FastAPI 继续负责业务。前端、BFF、API 可以分别构建、测试与版本化。浏览器访问仍保持同源，不以跨域直连实现“分离”。

代价是必须迁移 Next 当前隐含承担的流式 body、Cookie、Origin、错误转换和路由匹配，并验证完整上传、下载、SSE、登录与恢复；增加一个独立服务构建和运行边界。这个成本是选 B 的实际内容，不能只建立一个 Vite 目录即宣称分离完成。

同仓库独立包优于现在就拆仓库：可原子评审契约与兼容测试，分别产出镜像/静态包即可实现独立发布。后续拆仓库不是本次前提。

## 5. 信息结构与页面覆盖

### 5.1 首页

首页以“我的笔记本”为中心：最近打开、全部笔记本、名称搜索、新建、项目导入。卡片只显示标题、资料数量、更新时间和可选说明。无运营 dashboard、全局任务墙或模型设置卡片。

新建只要求名称，说明可选；创建后进入笔记本空状态。空状态只给“添加资料”和简短能力说明。示例问题在有可用资料后出现，不自动发送模型请求。

### 5.2 笔记本

顶栏包含返回、笔记本名称、上下文菜单、设置；资料、对话、成果是稳定的三个功能区。读原文是围绕来源/引用展开的工作面，不是与对话互斥的中央页签。

NotebookLM/独立模型属于当前笔记本的能力与范围设置。提问旁用一句话说明“基于 X 份资料”；引擎名及限制可以展开。不得静默替换 NotebookLM，也不得把本地勾选伪装成远端范围。

### 5.3 全部现有页面的去向

完整切换前必须完成旧路由/能力清单，逐一标明“新界面覆盖、兼容展示、明确不可用及原因”；没有归属的功能阻止最终替换。

- 笔记本列表、详情、study：统一新笔记本体验，已有 ID、深链接继续有效。
- 全局来源与来源详情：保留在资料库次级入口，支持既有来源类型及原有操作；笔记本内不因此增加第二套资料流程。
- 全局搜索/Ask：保留在全局搜索入口，明确与当前笔记本选源搜索不同；不可将其结果误当选定范围回答。
- 播客/音频：统一成果中心，保留已有任务、播放、下载和显式重试能力。
- 模型、提供方、连接、应用设置：新设置中心；保存/验证状态清楚，不在首页展示密钥或技术日志。
- transformations、advanced、embedding maintenance：置于设置内的高级工具，新 UI 包装现有明确操作和警告，不能静默移除。
- 经典资料/聊天历史中尚未进入新证据模型的内容：新界面提供兼容来源行、历史阅读与既有受支持操作，不伪造版本、引用或派生 provenance，不把迁移视图等同于数据迁移。
- 登录、重新认证、连接失败、未找到、版本不兼容：采用同一设计系统，不能保留上游更新通知或把上游版本当本产品升级。

分阶段预览可以先覆盖主旅程，但必须标明尚未覆盖部分；这不是“全部前端重做”最终完成。旧服务在验收期间保留，切换完成后不再依赖 Next 运行时提供任何正常用户功能。

## 6. 核心交互

### 6.1 添加、选择与管理资料

“添加资料”统一容纳本地文件、网页发现、已有资料和受支持的 NotebookLM 导入；按当前真实能力显示。初始文件能力沿用 PDF、Markdown、纯文本，不借重做宣称新增 OCR/Office 解析。

资料行默认只显示名称、类型、必要状态和选择框。点击标题阅读；选择框只改变问答范围。版本历史在来源详情中，当前选定版本以日期/短标识可辨；历史版本不得被自动升级为“最新”。不同版本可成为独立选定依据，沿用最多 20 个版本的服务端限制。

上传后在原位置显示进度阶段：发送、已接收、解析、可用、失败/待核对。失败有明确的下一步；未知结果先核对已有身份，不生成新幂等键重传。文件对话框取消不报错。拖放区只在有效文件拖入时出现，不让整个页面常驻大框。

新导入资料不自动改变已有问答范围。导入成功给出清楚的“用于接下来的提问”显式操作；首次空笔记本同样不隐藏此步骤。网页发现输入不会自动搜索，选中结果后才导入；结果摘要不是全文证据。

### 6.2 对话与追问

连续消息流为主，底部输入框固定在本区域，范围摘要紧邻输入框。Enter 发送、Shift+Enter 换行，中文输入法组合状态不发送；键盘行为可在触控端保留发送按钮。正在提交时同步阻止双击，消息草稿不在请求真正接纳前丢弃。

问答结果显示引用、必要的覆盖不足/未验证提示和“保存到成果”。来源/检索细节放在结果详情中，核心限制不得藏在 tooltip 里。错误与恢复操作贴在对应问题旁，不滚出全局红色日志。

保留当前服务端聊天/session 语义。连续对话的视觉不代表自动把上一轮答案提升为证据，也不承诺当前 API 未证明支持的上下文记忆。若服务端按独立问题执行，输入区必须如实说明；要新增真正的多轮推理上下文，单独定义受限历史契约后再开放，不让新 UI 虚构能力。

SSE 阶段为“已接收 / 处理中 / 完成”等持久状态。只有实际 token 事件被另行定义与验证后才能逐 token 展示，初版不做假打字机动画。

### 6.3 引用与阅读

点击引用打开对应版本与物理页/文本位置，并显示来源标题、引用原文及验证状态。可同时看到原回答；关闭后回到原消息和滚动位置。无法可靠定位时保留原文并说明，不猜页码，不跳到同名文件。

PDF 支持适宽、原尺寸、缩放和页码；放大只让阅读视口滚动。正文文本可搜索、复制，公式、代码、表格有局部宽内容策略。原件不可用、无提取文本、当前筛选无匹配是三种状态。

阅读操作不改变问答选源。最新的手动翻页优先于迟到引用定位请求；打开不同笔记本、来源或版本时退休旧请求。原文查看不触发 Google 写入或模型调用。

### 6.4 笔记和成果

成果列表展示标题、类型、更新时间及生成状态，默认不是一直打开的空编辑表单。打开/新建笔记后才进入编辑面板，标题可就地编辑，正文使用安全 Markdown 编辑/预览。保存按钮与保存状态固定在编辑区域。

保存明确区分未保存、保存中、已保存、冲突和结果待核对。服务端 revision 是事实来源；409/428 保留本地草稿，给出比较/重新载入入口，不自动合并或覆盖。未知结果不能通过重复按保存生成第二份。

“保存回答”保留内容、引用和冻结范围。“作为资料使用”是另一个明确操作，只处理已保存的权威版本，不自动保存脏编辑器；派生成果保持可辨识且不能算独立佐证。

音频等生成能力只在真实 capability 可用时出现可执行按钮；任务在对应成果卡片展示。取消必须区分“停止等待”和已证实的远端取消，不能给出虚假成功状态。

### 6.5 草稿和导航

同一页面会话中，切页签、开设置、看引用、窗口缩放和应用重新认证不得丢问题草稿、笔记草稿、File 对象与未知操作身份。路由导航改变编辑目标时先确认；笔记本切换不能把旧草稿发送到新目标。

本次默认保留内存草稿，不增加浏览器磁盘资料缓存或离线写队列。刷新/关闭页签前提示未保存内容，不能保证浏览器强退后恢复；这是明确的首版取舍，不声称已实现持久草稿。刷新后恢复已确认的服务端任务身份与历史；不能仅凭相同 URL 把未决凭据/操作状态跨人类身份恢复。若用户要求强退恢复，需追加受保护的本机草稿存储设计，不把它混成跨设备同步。

## 7. 桌面、平板与手机布局

断点按可用空间和内容约束选择，不按设备型号猜测。下面是起始布局规则，具体 px 可由实现者在最小正文宽与真实字体下校准。

- 宽桌面（约 ≥1280 CSS px）：资料侧栏 + 主工作区 + 成果侧栏。开启阅读时优先收起成果，主工作区分成对话与阅读；若宽度不足则资料也收为抽屉。禁止硬塞四栏。
- 中等桌面/横屏平板（约 900–1279）：对话 + 阅读/成果的双栏，资料使用抽屉；未打开阅读时对话更宽。平板分屏降为手机或单栏规则。
- 窄屏（约 <900）：资料／对话／成果单区域导航；引用打开全屏阅读器，通过系统返回或显式关闭回到对应回答。
- 手机使用底部主导航及安全区域留白；弹出键盘不能遮住输入和发送按钮，输入框不会把历史顶出不可访问区域。

侧栏可折叠并在支持鼠标的宽屏上调宽；布局偏好不包含隐私内容。重设宽度和恢复默认始终可用。正文维持舒适行长，宽表格/代码/PDF 在本地视口内横滚，页面本身不横向溢出。200% 缩放、大字体和粗指针仍可操作；关键触控目标至少 44×44 CSS px。

## 8. 视觉与无障碍方向

方向是黑白灰、安静、清楚、有层次的研究工具。此项来自用户明确偏好：“但是我很喜欢那种黑白灰的设计的美学风格”。浅色用近白背景、白色内容面和黑色主操作，深色用近黑背景、分层深灰内容面和近白主操作。引用、选中、AI、成功、警告、错误和危险操作均用不同图标、明确文案、边框、字重及位置识别，不依赖红/绿/蓝等彩色。原始资料中的图片、图表和媒体保持原色，不为界面美学篡改内容。旧 Quiet Green 与先前提议的蓝色均被此要求替代。

统一 4/8 px 间距阶梯、少量圆角与边界、克制阴影。默认正文约 16 px，工具文案不以极小字堆信息；标题层级靠字号/字重/留白共同区分。优先复用或系统字体，不在运行时引入远程字体请求。浅深色都通过语义 token 定义，不复制散落的颜色值。用户可明确选择浅色、深色或跟随系统；首次未选择时跟随系统，手动选择后保持到再次更改。偏好仅本机存储，不保存文档或凭据；跨页/刷新保持，不承诺跨设备同步。启动时在首帧应用主题以避免亮暗闪烁；切换不重建工作台、不丢草稿、PDF 页码或对话滚动位置。

内容密集的控件使用渐进披露，不隐藏关键限制。加载用尺寸稳定的 skeleton 或局部状态，避免全屏 spinner 和整页闪动。常驻成功 toast 改为就地轻量反馈，错误保留可操作说明。

键盘焦点、页签语义、输入标签、屏幕阅读器播报、modal 焦点返回与 Escape 行为均作为功能验收；动画遵守 reduced-motion，不让动效改变阅读位置。正文和按钮文字对比度 ≥4.5:1，适用的大字 ≥3:1，必要非文字边界 ≥3:1。不能仅靠颜色区别选中、失败和引用可信度。

### 8.1 用户博客参考与应用化

用户随后提供博客 https://gm-2.zhou-chu.workers.dev/ 及截图，并说“比如这是我的博客的风格，我很喜欢，也可以调节深色和浅色风格”。已实际查看原图和在线黑白浅/深两种界面；参考图与测量记录见 [视觉参考](../references/notebook-blog/README.md)。

采用其纸墨语汇：中文宋体粗标题、无衬线工具栏、等宽小标签、细分隔线、直角或极小圆角、反白主按钮。起始浅底 #EEEEEB/主字 #151515/次字 #5A5A55；深底 #121212/内容面 #191919/主字 #E8E8E4/次字 #A3A39D。标题优先 Noto Serif SC、Songti SC、STSong 系统栈，工具栏用系统 sans；正文与阅读区以实际可读性校验，不把博客近两倍的行高用于密集工具栏。

博客同时有“黑白/自然”和“深色/浅色”两套切换；Notebook不增加另一套自然配色，保持黑白灰，只提供浅/深和跟随系统。资料媒体不加全局灰度滤镜。博客的刷新持久化/系统跟随未验证，Notebook的对应行为按本设计单独实现。

不搬入大型 Hero、建筑摄影、背景纹理或六列高卡片；首页标题收敛至32–40px，工作台标题20–24px。工作台利用屏幕宽度，只有阅读正文约束行长，而不是把整个应用套进博客居中窄容器。

## 9. 应用与代码边界

拟定同仓结构：

- apps/web：Vite 构建的 React SPA，页面、UI、浏览器平台适配。
- apps/bff：独立 Node 服务，浏览器会话与受限代理；不包含 React、Next 或产品业务数据库。
- packages/contracts：公开 DTO、兼容规则、已批准的 OpenAPI/fixture 派生内容。
- packages/domain：无 DOM 的选择/任务/编辑状态与纯规则。不要把框架 hook、Cookie 或平台凭据装入“共享核心”。
- packages/web-transport：浏览器专用同源请求、认证协调与取消；显式不供 ArkTS 直接复制。
- api、open_notebook、worker 现有目录：后端业务事实来源。

模块名可由实施者调整，但依赖方向不可倒置。Web 页面不读 auth storage、不拼服务器 URL、不直连 Google/模型、不调用数据库。BFF 不重写证据有效性、不推断笔记 revision、不保存业务资料、不把任务轮询变成调度器。原生客户端共享协议与 fixtures，不强行共享 UI 或浏览器 transport。

Query 管理服务端数据；草稿/面板状态与 mutation 生命周期分开。所有 mutating 操作显式 retry:false；查询仅在按端点分类允许时有界重试，不能照搬库默认行为。关键状态机在 UI 外可独立测试，UI 只负责呈现与用户意图。

## 10. 契约与能力适配

沿用 /api 与 /api/personal 路径，不为命名整洁而整体搬到新版本前缀。导入/引用/任务 ID、缺失与 null、历史未知枚举都保持兼容。

建立稳定公开读模型，明确来源、版本、证据、笔记、turn、job、范围和能力字段；内部 file_path、凭据、提供方原始错误不得进入新公开投影。投影只能去掉已判定为内部的字段，不能丢失合法 provenance、未知历史信息或改变写入语义；旧 workspace 端点在兼容窗口保留，新公开端点/版本化表示先由契约阶段冻结。新 SPA 不把旧 opaque JSON 当成自动可操作的数据。

OpenAPI/fixtures 与实际应用输出一致。未知 engine/origin/state 只读显示为不可用，不自动归为默认引擎；不认识的能力不能授权按钮。历史内容有独立只读投影，不把 restore 历史任务恢复为可执行工作。

请求边界覆盖：选源上限和 notebook membership；真实 version/evidence identity；expected_revision；幂等键及请求摘要；提交状态；下载 MIME/大小/文件名/哈希；已支持的错误 envelope。具体结果仍不完全类型化者先逐端点补齐，不用 any 掩盖安全动作选择。

多端笔记写入遵守已有条件更新协议。启用 multiclient 必填模式属于明确配置与验收步骤，本次 UI 重做不默默切换运行模式；兼容旧 Web 的时期仍按既有模式执行，所有新编辑请求始终携带已读 revision。

## 11. 独立 BFF、入口与认证

### 11.1 生产路由

浏览器访问一个现有受保护 HTTPS origin：静态资源和 SPA 页面由静态服务提供；/api/* 只路由至 BFF；BFF 只连固定的内部 FastAPI 地址。数据库与 API 不因 SPA 独立发布而暴露到公网。

独立部署不要求不同域名。静态包可单独替换，BFF/API 各自独立镜像；已有 Cloudflare Access 和受支持隧道保留。入口 Cookie 在浏览器到同源入口这一段保留，BFF 不把入口 Cookie 或任意客户端认证头转发给 FastAPI。允许的方法、路径、请求/响应头、正文限制均为明确 allowlist；禁止任意 URL 代理和跨域重定向泄密。

### 11.2 初次切换策略

第一次生产切换以当前 legacy_password 行为兼容为准，不捆绑 device_sessions 的实际启用。迁移已测试的 legacy 浏览器与代理契约，保留现行凭据生命周期，不新增密码保存位置、不增加浏览器持久凭据副本、不降低入口认证。它仍是兼容模式，不称作已完成多设备认证。

独立 BFF 同时迁移现有已测 device-session 代码与测试，但未通过模式激活门禁时关闭。device 模式中浏览器只持 HttpOnly Secure SameSite 不透明句柄，native access/refresh 留在有界 BFF 内存；固定 Origin+CSRF、单飞刷新、严格一次性 refresh、未知结果退休句柄、服务端撤销等现有协议不变。

模式启用是后续明确操作：单进程 BFF 的容量、绝对期限、API boot epoch、撤销和 BFF/API 联动重启验收均通过后，才可经批准协调切换。不得在同一 origin 混跑旧密码 Web 和新 session Web，或靠持久 token 缓存、提高上限掩盖恢复问题。

### 11.3 重新认证与身份变化

应用会话失效时保存当前内存工作，显示重新认证层，不卸载整个工作台；仅恢复已确认有效的相同目标/身份范围。Google NEEDS_REAUTH 与应用登录失效分别显示。Cloudflare Access 过期的 HTML/重定向必须识别为入口认证问题，不能被当 JSON 解析错误或误报文件上传失败。

无法确认身份连续性、服务目标变化或撤销时冻结未决写操作；新的用户动作重新捕获上下文。既有 Authorization、Origin、CSRF 和固定上游边界测试要原样保留并在独立 BFF 上重跑。

## 12. 流、上传、下载与失败恢复

BFF 保持背压和增量 body 传递，不默认把整个 PDF/ZIP/SSE 缓冲进内存；multipart boundary 由浏览器生成；既有 body 限制、超时、取消及错误脱敏保持明确。不得通过无限大小或延长所有超时解决代理问题。

SSE 使用受控 fetch streaming，沿用分片缓冲、完整 JSON 事件和有界 EOF 行为。前端离开页面可以停止等待，不自动重新提交任务。断流后读取已知稳定 job/turn 身份，只有协议支持时恢复已有流，不制造新的运行。

任务 GET 可能恢复现有派发，不是普遍无副作用查询。对这类端点关闭 prefetch、通用 retry、离线自动恢复和焦点并发刷新；每任务只有一个协调观察者，按现有授权恢复语义运行，前后台切换去重。已有 workspace 的 2 秒轮询先兼容，不把性能优化和身份语义修改绑在第一次迁移；之后可增加轻量状态端点，需独立契约。

上传已接纳但回执丢失：保留原幂等键、文件与目标；先核对，不自动创建新请求身份。用户换文件/目标后是新意图，不复用旧键。超过限制在提交前提示，服务端仍执行相同限制。跨设备或刷新后无法重新获取 File 时要求用户重新选择并核对，不宣称可以无条件续传。

下载只接受应用资源 ID 与受保护路径，不接受任意服务端文件路径；流式转发、净化文件名、正确 MIME/Content-Disposition，禁止跨域携带凭据。空文件、权限拒绝、下载中断和哈希失败分别处理。浏览器保存对话框出现不代表下载完整。

笔记与生成的未知提交、409 冲突、认证拒绝、明确未发送需分别呈现。只有证明未发送或协议明确可重复的操作才允许对应重试；未知结果先核对，不采用统一“重试”按钮。

## 13. 构建、部署和迁移

前端构建不需要 API 在线或真实凭据，输出静态带内容哈希资源；BFF 构建不包含前端 bundle；API 不包含 React/Next。运行配置由受限同源配置接口提供且只含公开字段。静态资源不可携带秘密、用户资料或提供方配置。

五个逻辑服务：静态 Web/gateway、BFF、API、worker、DB。BFF 单实例；API/worker 延续已支持的单机共享数据根与文件锁边界。不要从拆包推导出横向扩容。需要新的容器运行声明时，将原 frontend 服务拆为 web + bff，API/worker 使用相同后端源码/依赖版本。

前端可独立发布的条件是兼容窗口真实存在。静态启动握手校验 UI 支持的契约与 BFF 能力，应用登录后再从受保护的只读 API 能力端点取得真实 API 契约能力，不能把 BFF 自报版本当 API 已就绪；不兼容时保留安全只读/更新提示并冻结写操作，不能静默重试或自动强刷丢草稿。index.html 不长期缓存，哈希资源可缓存；本次不加 service worker，避免凭据和旧 bundle 缓存产生新边界。

迁移顺序：

1. 冻结上传修复后的权威代码、运行补丁差异和契约测试；不从旧云端 checkout 覆盖台式机部署。
2. 在隔离数据与测试入口运行独立 SPA/BFF，完成旧端点契约和负向安全测试，不连接真实笔记做自动验收。
3. 完成全页面覆盖清单与主旅程视觉/浏览器验收；用真实 provider 的测试需单独的既有授权和预算。
4. 生产切换前确认一致备份、静态/BFF/API 版本组合、入口路由、上传修复和退回版本；没有真实恢复演练不能称为可迁移部署完成。
5. 切换时避免新旧前端同时向同一数据库发起不兼容写入；保留可回退旧静态/BFF/代码组合。若未改 schema，回退不需恢复用户数据；若实施中发现必须破坏性迁移，停止并另作设计/批准。
6. 核验实际服务身份、登录、上传、问答、引用、保存/重开、导出；通过后才将新界面作为默认。旧 Next 可保留停止状态的回退产物，不再是新 UI 的运行依赖。

设计批准不等于实际修改域名、入口安全设置、凭据、运行模式、数据库或生产切换授权。实现阶段遵守对应动作的现有许可，不追加付费服务或公开访问。

## 14. 验收矩阵与完成条件

每项证据必须绑定代码提交、前端构建、BFF/API 版本、模式、浏览器/视口和时间。旧记录、jsdom、颜色计算不能代替当前像素/触控验收。结果分为通过、失败、未运行、受阻。

### 产品与视觉

- 360/390/768/1024/1280/1440/1920 px；中文/英文；浅/深色；键盘/粗指针；125%/200% 缩放；平板分屏和手机键盘。
- 从新建、添加资料、选源、提问、查看引用、保存成果到重开，操作与状态清楚；点击引用不丢原回答上下文。
- 长标题、长 URL、双栏论文、公式/代码/表格、同日多版本、无资料/无匹配/原件缺失、失败/未知结果；页面无横向溢出。
- 模态框确认/取消/Escape、返回/前进、重复点击、焦点恢复、文本选择复制、阅读位置；拖动面板不挤坏正文。
- 浅色/深色/跟随系统切换、首次启动与刷新无明显闪烁、手动偏好不被系统变化覆盖；灰阶下选中、焦点、成功、失败、危险操作均可分辨，主题切换不重置工作。
- 所有旧可访问资料/历史/操作都有新界面归属，不因默认路由变化消失。

### 协议与安全

- 同源 Cloudflare Access Cookie 保持；跨源 Cookie/Bearer 不泄漏；固定内部 upstream、无任意代理；异常 HTML/重定向识别。
- 当前 legacy 模式完整回归；device 模式单列未启用/测试证据，不合并为一个绿灯。
- 401、403、503、撤销、身份/目标 A→B→A、同页并发、迟到响应；旧请求不能在新目标恢复执行。
- 未知上传/生成/保存/下载、断流、取消、超限文件、chunked body、丢回执；请求计数证明没有重复副作用。
- revision 冲突、必填 revision、历史引用/恢复来源、派生资料、未知枚举和 null/缺失；只读展示不放行操作。

### 工程与交付

- 独立 web 和 BFF 的 lint/types/unit/build；后端相关套件；实际 OpenAPI/fixtures 兼容检查；无 Next 运行依赖；无秘密进入产物。
- 真实浏览器端到端与 BFF/API/worker/DB 集成，按独立测试数据与入口运行。
- 部署候选实际启动、就绪、停止/恢复、数据卷和入口验证；Docker 未实际构建运行则不宣称 Docker 交付完成。
- 真实模型/NotebookLM 能力按其原有门禁验收，模拟 provider 仅证明 UI 和协议，不证明能力可用。
- 无障碍抽查与至少一次面向用户主旅程的独立评审。工程绿灯不自动等于“好看、好用”，需用户对实际新界面确认。

## 15. 实施者可以自行决定的内容

可以自行确定组件拆分、状态机的库或纯实现、目录命名细节、精确断点、表单库、图标集、细小 spacing、测试文件组织，只要满足上述边界并优先复用已准备依赖。

不可自行改变：方案 B、全部前端覆盖目标、服务端事实来源、选源/阅读分离、引用版本、条件笔记写入、未知提交处理、入口私密性、认证模式激活、原生技术路线、数据迁移和发布权限。新依赖、视觉色值和性能阈值应在计划中说明理由，不能默认为用户明确选择。

此稿不建立新项目、不安装依赖、不编写产品代码。总体设计已确认，下一步只编写逐项实现计划并自查；实施和生产操作仍有各自的审阅与许可边界。
